# 00 战斗系统总览

## 1. 设计目标

复刻原神战斗的三个不可替代特征：

1. **元素是一等公民**：伤害属性不是装饰性标签，而是通过「附着 → 反应」形成独立于数值面板的第二套玩法层。任何角色设计都必须能在反应矩阵上找到位置。
2. **四人一队的轮转节奏**：单角色输出窗口被 CD、能量与反应时间共同切割，玩家的核心操作是**切人序列**而非单角色连招。
3. **开放世界即战场**：战斗不存在独立的「战斗场景」，移动、探索、地形与战斗共用同一套角色控制器与同一套元素规则（水面结冰可行走、雷附着触发环境机关等）。

## 2. 模块边界

复刻后的战斗系统按职责划分为下列模块。括号内是本项目当前对应目录，`（新增）`表示需要建立。

| 模块 | 职责 | 对应目录 |
| --- | --- | --- |
| 角色控制器 | 位移、跳跃、攀爬、游泳、滑翔、体力消耗 | `EntitySystem/Character/Logic/`（扩展） |
| 动作驱动 | 动画语义、连段窗口、取消规则、根运动 | `Animation/` |
| 天赋动作 | 普攻/重击/下落/E/Q 的触发、CD、消耗 | `EntitySystem/Character/Logic/Talent/` |
| 元素系统 | 附着量、衰减、ICD、反应判定与结算 | `ElementSystem/`（新增） |
| 伤害结算 | 面板聚合、乘区计算、暴击、防御区、抗性区 | `EffectSystem/` + `Combat/`（新增） |
| 效果系统 | Buff/Debuff/DOT/护盾的施加、堆叠、刷新 | `EffectSystem/` |
| 队伍系统 | 编队、切人、元素共鸣、场外状态维持 | `TeamSystem/` |
| 敌人 AI | 感知、仇恨、行为选择、相位切换 | `Ai/`、`EntitySystem/Monster/` |
| 受击反馈 | 硬直等级、击退、霸体、控制状态 | `EntitySystem/Common/AttackedLogic.cs`（重构） |
| 战斗表现 | VFX、震屏、命中停顿、音频、飘字、血条 | `EffectSystem` + `CombatAudioPresentationSystem` + `UI/` |

模块间依赖必须遵循 `Docs/Arch/ArchSpec.md` 第 6 节的 `ARCH-SYS-005`：公共 System 之间通过构造注入 `I*System` 契约建立依赖，禁止在 System 实现内服务定位。

## 3. 一次攻击的完整数据流

这是全系统最重要的一条链路，所有案子都围绕它展开。

```text
输入
 └─ InputSystem 产出 CombatAction 意图
     └─ TalentLogic 分派到 NormalAttack / Charged / Plunge / Skill / Burst
         ├─ 校验：控制状态、CD、能量、体力
         ├─ 扣除资源，进入动作状态
         └─ AnimationPlayback 播放动作
             └─ 动画事件在指定帧开启 Hitbox
                 └─ Hitbox 命中目标，产出 HitInfo
                     ├─ ① 元素附着判定（ICD 门控）→ ElementSystem
                     │    └─ 写入/消耗目标 ElementAura，判定反应类型
                     ├─ ② 反应结果回填到 DamageContext（增幅倍率 / 激化加算）
                     ├─ ③ 伤害结算 DamageCalculator
                     │    基础伤害 → 增伤区 → 暴击区 → 增幅区 → 防御区 → 抗性区
                     ├─ ④ 扣血、护盾吸收、死亡判定
                     ├─ ⑤ 剧变反应独立结算（不吃攻击者面板）
                     ├─ ⑥ 硬直判定 → AttackedLogic
                     ├─ ⑦ 能量产出（元素微粒生成）
                     └─ ⑧ 表现信号：飘字、VFX、音频、震屏、命中停顿
```

顺序约束（必须严格遵守，顺序错误会导致数值偏差）：

- **① 必须早于 ③**：反应类型决定增幅乘区，附着判定必须在伤害计算前完成。
- **⑤ 必须晚于 ③**：剧变伤害是独立结算的第二笔伤害，不参与本次攻击的乘区。
- **④ 必须晚于 ③⑤ 全部完成**：同一帧内的多笔伤害统一结算，避免中途死亡吞掉后续反应。
- **⑦ 的微粒生成时机跟随动作而非命中**：部分技能无论是否命中都产球，见 `03`。

## 4. 术语表

| 术语 | 英文 / 代码名 | 含义 |
| --- | --- | --- |
| 附着量 | Gauge Unit（GU） | 元素附着在目标身上的量，决定持续时间与反应消耗 |
| 附着 | Aura | 目标身上当前存在的元素状态 |
| 内部冷却 | ICD | 同一来源的元素附着冷却，默认 2.5 秒 / 3 次 |
| 增幅反应 | Amplifying | 蒸发、融化。作为独立乘区放大本次伤害 |
| 剧变反应 | Transformative | 超载、超导、感电、扩散、碎冰、绽放等。独立结算，不吃攻击面板 |
| 激化反应 | Catalyze | 超激化、蔓激化。以加算形式提升基础伤害 |
| 元素精通 | Elemental Mastery（EM） | 影响全部反应强度的专用属性 |
| 元素能量 | Elemental Energy | 元素爆发的消耗资源 |
| 元素微粒 | Elemental Particle | 元素战技产出的能量拾取物，基础值 1 |
| 元素晶球 | Elemental Orb | 高价值能量拾取物，基础值 3 |
| 元素充能效率 | Energy Recharge（ER） | 能量获取倍率 |
| 硬直等级 | Poise / Stagger Level | 攻击的打断能力与单位的抗打断能力 |
| 上场角色 | On-Field | 当前被玩家操控的角色 |
| 场外角色 | Off-Field | 队伍中未上场的角色，仍可由持续效果结算 |

## 5. 与现有实现的关系

现有代码已具备可复用的骨架：

- `EffectSystem`（`EffectDefinition` / `EffectRuntime` / `EffectOperations`）可直接承载 Buff、DOT、护盾与反应产生的持续效果。
- `Animation/` 的 `AnimationLine` + Executor 体系可承载连段窗口与取消规则。
- `EntitySystem/Character/Logic/Talent/` 的四动作分层与 CD 逻辑结构与原神一致，主要缺重击与下落攻击。
- `TeamSystem` 已有上场成员概念，缺元素共鸣与场外结算。

需要**替换而非扩展**的部分：

- ~~`DamageAttributeRules` 的五行克制 ×1.3 模型~~ → 元素附着与反应模型。**已完成**，见 [90 差异台账](90_现有实现差异台账.md) 第 1.1 节。
- `PropertyConfig.coreEnergyLimit` / `ultEnergyLimit` 双能量 → 单一元素能量。
- `PropertyConfig.toughness` 的「打断能力 > 韧性即 Stun」布尔模型 → 分级硬直模型。

逐项改造清单见 [90_现有实现差异台账](90_现有实现差异台账.md)。
