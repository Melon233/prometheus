# 03 元素战技与元素爆发

## 0. 实现状态

**充能层数已落地**：`TalentConfig.skillChargeCount` + `SkillComponent` 的逐层回复。每层独立计时，消耗第二层不重置正在走的冷却——多段充能的意义正是「先放掉、边打边回」，重置等于取消这个收益。

**冷却缩减已接线**：`PropertyType.CooldownReduction` 在**进入冷却的那一刻**结算一次。每帧按当前缩减折算剩余时间的话，冷却期间换上减 CD 装备就能立刻缩短本次冷却，是可被玩家利用的行为。

尚未实现：点按/长按双版本、元素微粒与能量（排期第 6 步）、元素爆发的能量门槛。

## 1. 设计目标

E 与 Q 是角色的身份标识，也是队伍轮转的节拍器。复刻要点不在技能效果本身，而在**资源约束的精确性**：CD、充能层数、元素能量三者共同决定了「一轮循环多长」，任何一项偏差都会让配队体验完全走样。

## 2. 元素战技（E）

### 2.1 触发形式

| 形式 | 说明 |
| --- | --- |
| 点按 | 短按立即释放 |
| 长按 | 按住超过阈值（约 0.3 秒）释放不同版本 |
| 蓄力 | 按住持续蓄力，松手释放，蓄力程度影响效果 |
| 切换态 | 释放后进入持续状态，再次按下退出 |

一个角色可同时具备点按与长按两个版本，它们**共享同一条 CD**，但 CD 时长可以不同。

### 2.2 冷却

```text
实际 CD = 基础 CD × (1 - 冷却缩减)
```

- CD 在**技能释放的瞬间**开始计时，不等待动画结束。
- 冷却缩减上限 100%，但实际存在 0 秒保底。
- 现有 `SkillCooldownLogic` 已具备该结构，需补充冷却缩减属性接入。

### 2.3 充能层数

部分角色的 E 具备多层充能：

- 拥有 `MaxCharges` 层，每层独立恢复；
- 层数未满时持续恢复，恢复计时不因释放而中断；
- 释放消耗一层，有层数即可释放。

实现上以「恢复计时器 + 当前层数」表达，而非 N 个独立 CD。

### 2.4 元素微粒产出

E 是元素能量的主要来源。产出规则：

| 参数 | 说明 |
| --- | --- |
| 产出数量 | 固定值，或按命中数/概率产出 |
| 产出时机 | 多数在技能释放时，部分在命中时 |
| 产出元素 | 角色元素 |
| 是否需要命中 | 按技能配置，部分技能空放也产球 |

```csharp
// 描述一次元素微粒产出，由技能段落在指定时机发起。
public struct ParticleSpawn
{
    public ElementType Element;
    public int Count;              // 固定产出数量
    public float Probability;      // < 1 时按概率产出额外一颗
    public ParticleTiming Timing;  // OnCast / OnHit / OnKill
    public bool RequiresHit;
}
```

## 3. 元素爆发（Q）

### 3.1 释放条件

- 元素能量达到上限；
- 不在 CD 中；
- 角色处于可行动状态。

### 3.2 释放表现

元素爆发具备**全局特权**：

- 释放瞬间角色获得**无敌帧**（约 1 秒，覆盖前摇）；
- 播放专属过场镜头与角色特写；
- 释放期间队伍其它操作被锁定；
- 释放后能量清零。

### 3.3 能量清零时机

能量在**释放动画开始时清零**，而非结束时。这意味着释放期间获得的能量会被浪费，是配队循环设计中必须考虑的细节。

## 4. 元素能量系统

### 4.1 能量上限

由角色配置，常见 40 / 60 / 80。上限不可被提升。

### 4.2 微粒与晶球

| 类型 | 基础能量值 |
| --- | --- |
| 元素微粒（Particle） | 1 |
| 元素晶球（Orb） | 3 |

### 4.3 能量结算公式【实测】

拾取一颗微粒/晶球时，队伍中**每个角色**都获得能量：

```text
角色获得能量 = 基础值 × 元素系数 × 场上系数 × 队伍人数系数 × 元素充能效率
```

| 系数 | 取值 |
| --- | --- |
| 元素系数 | 角色元素 == 微粒元素 → 3.0；不同元素 → 1.0；无元素微粒 → 2.0 |
| 场上系数 | 上场角色 → 1.0；场外角色 → 0.6 |
| 队伍人数系数 | 1 人 1.0；2 人 1.0；3 人 0.8；4 人 0.7 |
| 元素充能效率 | 角色面板 ER |

【待复核】队伍人数系数与无元素微粒系数需实机确认。

### 4.4 微粒拾取

- 微粒生成后向角色缓慢飞行，需要角色靠近触发吸附；
- 存在时间约 30 秒后消失【待复核】；
- 拾取判定半径约 3 米。

### 4.5 其它能量来源

- 部分角色天赋直接回复能量（不经微粒，**不吃元素充能效率**，除非明确说明）；
- 部分武器与圣遗物提供能量回复。

## 5. 与队伍的交互

- 场外角色的 E/Q 产生的持续效果（场域、召唤物、附着源）**继续结算**，且其伤害使用**释放瞬间快照的角色面板**，而非当前面板。
- 面板快照是原神数值设计的关键约定：场外角色被替换下场后，其面板变化不影响已释放的持续效果。

```csharp
// 释放时对施法者面板做一次不可变快照，供持续效果全程使用。
public readonly struct CasterSnapshot
{
    public readonly int CasterEntityId;
    public readonly float Atk, Hp, Def, ElementalMastery;
    public readonly float DamageBonus, CritRate, CritDamage;
    public readonly int Level;
}
```

## 6. 技能配置结构

```text
TalentDefinition
 ├─ TalentId / TalentType(Skill|Burst)
 ├─ CastMode(Tap|Hold|Charge|Toggle)
 ├─ Cooldown / MaxCharges
 ├─ EnergyCost（Burst）
 ├─ InvincibilityWindow（Burst）
 ├─ ParticleSpawn[]
 ├─ AttackSegment[]        // 复用 02 的段落结构
 └─ EffectDefinition[]     // 复用现有 EffectSystem
```

持续效果、召唤物与场域由 `EffectSystem` 的 `EffectDefinition` 承载，不新建平行机制。

## 7. 验收用例

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| S-01 | 释放 E 后立即查看 CD | CD 从释放瞬间开始 |

| S-03 | 双层充能 E 连续释放两次 | 两层耗尽，恢复计时不重置 |

| S-09 | 场外角色场域伤害 | 使用释放瞬间的面板快照 |
