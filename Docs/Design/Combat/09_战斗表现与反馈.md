# 09 战斗表现与反馈

## 1. 设计目标

原神的打击感不来自单一手段，而是**六条反馈通道在同一帧内对齐**：动画、命中停顿、镜头、VFX、音频、UI 飘字。任何一条延迟一帧都会让手感变"软"。本案定义每条通道的触发时机与参数，以及它们之间的对齐约束。

## 2. 命中反馈时间轴

以一次命中为 0 帧：

```text
帧 0   ── Hitbox 命中判定成立
帧 0   ── 命中 VFX 生成（命中点位置与法线）
帧 0   ── 命中音效播放（无延迟，最优先）
帧 0   ── 命中停顿开始（攻守双方动画暂停）
帧 0   ── 目标材质闪白开始
帧 0-2 ── 震屏开始
帧 1   ── 伤害飘字生成并开始上浮
帧 N   ── 命中停顿结束（N 由攻击段落配置）
帧 N   ── 击退/位移开始施加
```

**硬约束**：音效必须与命中判定同帧，不得等待 VFX 加载。资源未就绪时宁可不播，不可延迟播放。

## 3. 命中停顿（Hit Stop）

短暂冻结攻守双方的动画播放，是打击感最主要的来源。

| 攻击强度 | 停顿时长 |
| --- | --- |
| 轻（普攻前段） | 0.03s |
| 中（普攻末段、重击） | 0.06s |
| 重（元素战技） | 0.09s |
| 极重（元素爆发、破盾） | 0.12s |

【自定】以上为起始参数，需在实机体验后调整。

实现约束：

- 停顿通过缩放动画播放速度实现，**不使用 `Time.timeScale`**（会影响 UI、VFX 与其它单位）；
- 只影响攻击者与被命中者，不影响场上其它单位；
- 停顿期间输入正常采集并排队，不丢输入；
- 多个停顿同时触发时取最长值，不叠加。

## 4. 镜头

### 4.1 震屏

| 参数 | 说明 |
| --- | --- |
| 强度 | 按攻击强度分档 |
| 时长 | 0.1 ~ 0.3s |
| 方向 | 攻击方向的垂直分量为主 |
| 衰减 | 随距离摄像机的距离衰减 |

震屏通过现有 `CameraSystem` 的扰动通道施加，与叙事镜头租约互斥：叙事演出持有镜头租约期间屏蔽战斗震屏。

### 4.2 元素爆发过场

- 释放 Q 时切入专属特写镜头；
- 镜头由 `CameraSystem` 的 `CutsceneCameraLease` 承载，复用现有机制；
- 过场期间玩家输入锁定，但**游戏时间不暂停**（敌人继续行动）；
- 过场可通过设置跳过。

### 4.3 战斗镜头微调

- 锁定目标时镜头略微偏移以同时容纳角色与目标；
- 大范围攻击时镜头短暂拉远；
- 这些调整必须可在设置中关闭。

## 5. VFX

| 类别 | 触发时机 | 归属 |
| --- | --- | --- |
| 挥舞拖尾 | 攻击动画指定区间 | 武器 |
| 命中特效 | 命中判定成立 | 伤害元素 × 目标材质 |
| 元素附着特效 | 附着写入成功 | 元素类型，常驻至附着消失 |
| 反应特效 | 反应触发 | 反应类型，一次性 |
| 技能特效 | 动画事件 | 角色专属 |
| 护盾特效 | 护盾生成/破碎 | 护盾元素 |

现有 `VfxComponent` 与 `EffectSystem` 的 `EffectOperations` 可承载，元素附着特效需新增常驻挂点类型。

## 6. 音频

复用现有 `CombatAudioPresentationSystem`（已依赖 `IEffectSystem`），扩展信号类型：

| 信号 | 音频 |
| --- | --- |
| 挥舞 | 武器类型 |
| 命中 | 武器类型 × 目标材质 × 是否暴击 |
| 元素附着 | 元素类型 |
| 元素反应 | 反应类型（超载、冻结、碎冰等各有专属音） |
| 护盾破碎 | 护盾元素 |
| 技能释放 | 角色专属语音 + 技能音效 |
| 受击 | 角色/敌人专属 |
| 死亡 | 敌人类型 |

所有音频经 FMOD 事件触发，不直接调用 `AudioSource`。

## 7. 战斗 UI

### 7.1 伤害飘字

现有 `FloatDmgComponent` / `FloatDamageKit` / `FloatDamageConfig` / `UI/FloatingDmgText` 已实现基础能力，需扩展：

| 样式 | 区分维度 |
| --- | --- |
| 颜色 | 八种元素 + 物理，各一色 |
| 字号 | 普通 / 暴击（暴击更大且带描边） |
| 前缀 | 反应伤害带反应名标签（"超载"、"蒸发"等） |
| 治疗 | 绿色带 `+` |
| 免疫/无效 | 灰色文字提示 |

飘字需做同帧合并：同一帧对同一目标的多笔伤害分散上浮，避免完全重叠。

### 7.2 HUD

| 元素 | 内容 |
| --- | --- |
| 队伍栏 | 4 个角色头像、血条、元素能量环、E 冷却、Q 就绪高亮 |
| 体力条 | 消耗时显示，满时淡出 |
| 敌人血条 | 世界空间，含元素护盾条与附着图标 |
| Boss 血条 | 屏幕顶部，含相位分段标记 |
| 附着指示 | 敌人身上当前附着的元素图标，多元素并排 |

现有 `WorldHpBarLogic` / `HpBar` 承载世界血条，需扩展护盾条与附着图标。

### 7.3 元素能量环

- 环形进度显示当前能量 / 上限；
- 能量满时播放就绪动效并常亮；
- 场外角色能量同步显示。

## 8. 表现与逻辑的边界

按 `ArchSpec` 的 `ARCH-DATA-001`，表现层不得持有权威战斗状态。约定：

- 伤害管线在结算完成后发布**表现信号**（如 `CombatHitSignal`），携带完整只读快照；
- 表现层订阅信号并自行决定播放什么，不反向查询战斗状态；
- 表现层的任何缺失（资源未加载、特效被裁剪）不得影响战斗结算结果。

```csharp
// 一次命中产生的完整表现快照，发布后不可修改。
public readonly struct CombatHitSignal
{
    public readonly int SourceEntityId, TargetEntityId;
    public readonly Vector3 HitPoint, HitNormal;
    public readonly ElementType DamageElement;
    public readonly float FinalDamage;
    public readonly bool IsCritical;
    public readonly ReactionType Reaction;      // None 表示未触发反应
    public readonly int StaggerLevel;
    public readonly float HitStopDuration;
    public readonly bool ShieldAbsorbed;
}
```

## 9. 验收用例

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| P-01 | 普攻命中 | 音效、VFX、飘字、停顿在同一帧发生 |
| P-02 | 命中停顿期间按 E | 输入被记录，停顿结束后立即执行 |
| P-03 | 命中停顿 | 场上其它敌人动作不受影响 |
| P-04 | 触发蒸发 | 飘字带"蒸发"标签，播放专属音效 |
| P-05 | 元素爆发释放 | 切入特写镜头，敌人继续行动 |
| P-06 | 叙事演出期间受击 | 不产生震屏 |
| P-07 | 同帧对同一目标 3 段伤害 | 3 个飘字分散显示不重叠 |
| P-08 | 敌人带火附着 | 世界血条旁显示火附着图标 |
| P-09 | 击破元素护盾 | 播放破盾音效与 VFX，血条护盾段清空 |
| P-10 | 关闭震屏设置 | 战斗震屏不生效，其余反馈正常 |
