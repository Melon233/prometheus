## 阅读顺序建议

策划：`00 → 04 → 04A → 05 → 05A → 02 → 03 → 06 → 07 → 08 → 01 → 09`
程序：`00 → 90 → 04 → 04A → 05 → 05A → 其余按排期`

带 `A` 后缀的是**配表级附录**：把对应主案的规则落成可直接交给策划填写、交给导表工具消费的 Excel 表结构。主案定义「规则是什么」，附录定义「这条规则的数据长什么样」。两者冲突时以主案为准，并同步修正附录。

## 配表管线

全部配表走 Luban：策划在 `Data/Excel/` 维护 `.xlsx`，导表生成 C# 代码到 `Assets/Gen/Config`、二进制数据到 `Assets/BundleResources/Table`。目录职责、表头规范、类型写法与新增表的步骤见 [Docs/ConfigPipeline.md](../../Workflow/ConfigPipeline.md)，设计文档不重复定义。

导表入口：Unity 菜单 `Prometheus/Luban/导出配表`，或 `Tools/Luban/gen.bat`。

元素附着与反应（04）是整个战斗系统的中枢：它反向约束角色技能设计、敌人护盾设计、数值全局与表现层。任何其它案子与 04 冲突时，以 04 为准。

## 数值置信度标记

正文中的数值带如下标记：

- **【实测】**：社区通过大量实测反推、已被广泛验证的公式或常数，可直接实装。
- **【待复核】**：结构确定但具体数值需在实装前用原神实机再次确认，禁止直接上线。
- **【自定】**：原神未公开且无法实测的部分，由本项目自行定义，需在评审中确认。
