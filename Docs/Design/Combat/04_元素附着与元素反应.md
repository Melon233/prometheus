# 04 元素附着与元素反应

> 本案是战斗系统的中枢规则。与其它案子冲突时以本案为准。

## 1. 设计目标

元素系统解决一件事：**让「用什么打」和「打多少」成为两个独立的决策维度**。玩家配队时考虑的是反应链，配装时才考虑面板。要达成这一点，附着必须是一份有量、会衰减、被独立消耗的资源，而不是一个布尔标记。

## 2. 元素类型

七元素 + 物理。物理不参与任何附着与反应。

| 元素 | 代码名 | 备注 |
| --- | --- | --- |
| 火 | Pyro | |
| 水 | Hydro | |
| 雷 | Electro | |
| 冰 | Cryo | |
| 草 | Dendro | 附着规则特殊，见 5.4 |
| 风 | Anemo | 只作为反应触发方，自身不留存附着 |
| 岩 | Geo | 只作为反应触发方，自身不留存附着 |
| 物理 | Physical | 无附着、无反应 |

**风与岩不产生附着**：它们命中目标后立即结算扩散/结晶，自身不在目标上留下 Aura。

## 3. 附着量（Gauge Unit）

### 3.1 附着强度

每次元素攻击携带一个标称附着量，按强度分三档：

| 档位 | 标称值 | 典型来源 |
| --- | --- | --- |
| 弱附着 | 1U | 大多数普攻的单段、快速多段技能的每一段 |
| 中附着 | 2U | 多数元素战技、单段较重的攻击 |
| 强附着 | 4U | 元素爆发、部分大型技能 |

### 3.2 衰减税（Decay Tax）【实测】

写入目标的实际附着量并非标称值，而是：

```text
实际附着量 = 标称附着量 × 0.8
```

即 1U 写入 0.8U、2U 写入 1.6U、4U 写入 3.2U。

### 3.3 衰减速率【实测】

附着写入后线性衰减至 0。总持续时间由**标称值**决定：

```text
持续时间(秒) = 2.5 × 标称U + 7
衰减速率(U/秒) = 实际附着量 / 持续时间
```

| 标称 | 实际写入 | 持续时间 | 衰减速率 |
| --- | --- | --- | --- |
| 1U | 0.8U | 9.5s | 0.0842 U/s |
| 2U | 1.6U | 12.0s | 0.1333 U/s |
| 4U | 3.2U | 17.0s | 0.1882 U/s |

**关键推论**：衰减速率是在写入时按标称值锁定的，之后不随剩余量改变。这意味着重复施加同元素时，新的施加会同时刷新附着量与衰减速率。

### 3.4 同元素刷新规则【实测】

同元素再次命中时：

- 取 `max(当前剩余量, 新写入量)` 作为新的附着量；
- **衰减速率取新一次施加对应的速率**（即使新施加量更小也会重设速率）；
- 不叠加，永远不会超过单次写入的上限。

### 3.5 附着共存

同一目标身上可同时存在多个元素附着，但受限：

- **火 / 水 / 雷 / 冰** 四者中，任意两者相遇立即触发反应并互相消耗，通常只能共存 2 个（例如冻结状态下的冰+水）。
- **草** 可与火、水、雷共存或反应，见 5.4。
- 实现上目标持有一个 `ElementAuraSet`，每个元素一条 `Aura { Element, Gauge, DecayRate, AppliedAt }`。

## 4. 内部冷却（ICD）

### 4.1 规则【实测】

ICD 防止高频攻击无限刷反应。默认规则：

```text
每个 ICD 组：2.5 秒 或 3 次命中，先到者重置
```

判定流程：

1. 攻击命中时查询该攻击所属 ICD 组的状态。
2. 若该组处于「窗口未开始」或「已重置」状态 → **本次附着生效**，开启 2.5 秒计时并将计数置为 1。
3. 若窗口内且计数 < 3 → 计数 +1，**本次不附着**。
4. 若窗口内且计数达到 3 → 计数归零，**下一次命中附着生效**（即第 1、4、7… 次命中附着）。
5. 若距离窗口开始超过 2.5 秒 → 窗口重置，本次附着生效。

### 4.2 ICD 组划分

ICD 按 `(施加者, 天赋来源)` 划分，而非按元素划分。同一角色的普攻与战技是两个独立 ICD 组。

| 分组键 | 说明 |
| --- | --- |
| `SourceEntityId` | 施加者实体 |
| `TalentId` | 具体天赋（普攻 / 重击 / 战技 / 爆发 / 某个召唤物） |
| `Sequence`（可选） | 部分技能的不同段落使用独立 ICD |

### 4.3 无 ICD 的来源

下列来源**每次命中都附着**，配置上以 `icdPolicy = None` 表示：

- 元素爆发的单次命中（多数）；
- 部分设计为「持续附着」的场域类技能；
- 环境来源（水体、火堆、雷区）。

配置结构见 6.2。

## 5. 元素反应

### 5.1 反应总表

| 反应 | 组合 | 类型 | 效果 |
| --- | --- | --- | --- |
| 蒸发 | 水 + 火 | 增幅 | 火打水 ×2.0；水打火 ×1.5 |
| 融化 | 火 + 冰 | 增幅 | 火打冰 ×2.0；冰打火 ×1.5 |
| 超载 | 火 + 雷 | 剧变 | 火元素范围伤害 + 强击退 |
| 超导 | 冰 + 雷 | 剧变 | 冰元素范围伤害 + 目标物理抗性 −40%，12 秒 |
| 感电 | 水 + 雷 | 剧变 | 雷元素伤害，可在附着持续期间多次触发 |
| 冻结 | 水 + 冰 | 特殊 | 目标无法行动，可被重击类攻击碎冰 |
| 碎冰 | 冻结 + 钝器/岩/爆炸 | 剧变 | 物理范围伤害，解除冻结 |
| 扩散 | 风 + 火/水/雷/冰 | 剧变 | 对应元素范围伤害 + 对范围内目标降 40% 该元素抗性 10 秒 |
| 结晶 | 岩 + 火/水/雷/冰 | 特殊 | 生成对应元素结晶片，拾取获得护盾 |
| 燃烧 | 草 + 火 | 剧变(持续) | 持续火元素伤害 |
| 绽放 | 草 + 水 | 特殊 | 生成草原核，延时爆炸造成草元素伤害 |
| 超绽放 | 草原核 + 雷 | 剧变 | 草原核转为激化种子，爆炸伤害提升 |
| 烈绽放 | 草原核 + 火 | 剧变 | 草原核转为烈化种子，爆炸伤害提升 |
| 原激化 | 草 + 雷 | 状态 | 进入激化状态，为后续雷/草伤害提供加算 |
| 超激化 | 原激化 + 雷 | 激化 | 雷元素伤害加算 |
| 蔓激化 | 原激化 + 草 | 激化 | 草元素伤害加算 |

### 5.2 增幅反应

```text
增幅倍率 = 基础倍率 × (1 + 2.78 × EM / (EM + 1400) + 反应加成)
```
【实测】

- 基础倍率：正向 2.0（火打水蒸发、火打冰融化），逆向 1.5（水打火、冰打火）。
- `反应加成` 来自天赋、圣遗物套装等提供的「蒸发/融化反应提升 X%」。
- 增幅倍率作为**独立乘区**参与伤害计算，见 `05`。

**附着消耗**：增幅反应按 1:1 消耗附着量。正向（2.0 倍）消耗系数为 0.5，逆向（1.5 倍）消耗系数为 2.0 —— 即火打水时消耗的水附着为火附着量的一半，水打火时消耗的火附着为水附着量的两倍。【实测】

### 5.3 剧变反应

```text
剧变伤害 = 等级系数 × 反应倍率 × (1 + 16 × EM / (EM + 2000) + 反应加成) × 抗性区
```
【实测】

- **不吃攻击力、不吃增伤、不能暴击、不吃防御区。**只受等级系数、反应倍率、元素精通、反应加成与目标抗性影响。
- `等级系数` 按施加者等级查表，见 5.7。

| 反应 | 反应倍率 | 伤害元素 |
| --- | --- | --- |
| 超载 | 2.0 | 火 |
| 碎冰 | 3.0 | 物理 |
| 感电 | 2.4 | 雷 |
| 超导 | 1.0 | 冰 |
| 扩散 | 1.2 | 被扩散的元素 |
| 燃烧 | 0.25 / tick | 火 |
| 绽放 | 2.0 | 草 |
| 超绽放 | 3.0 | 草 |
| 烈绽放 | 3.0 | 草 |

【待复核】以上倍率需以实机数据二次确认后再入表。

### 5.4 草元素特殊规则

草的附着规则与四元素不同：

- **草 + 水（绽放）** 与 **草 + 雷（原激化）** 均**不完全消耗**双方附着；
- 原激化状态是独立于附着的一层状态，持续时间为 5～30 秒，由触发时双方附着量决定【待复核】；
- 原激化状态下，该目标受到的**雷元素**伤害触发超激化、**草元素**伤害触发蔓激化。

### 5.5 激化反应

```text
激化加算 = 等级系数 × 激化倍率 × (1 + 5 × EM / (EM + 1200) + 反应加成)
```
【实测】

- 超激化倍率 1.15，蔓激化倍率 1.25。
- 激化是**加算**：它加到基础伤害上，之后一起吃增伤、暴击、防御区、抗性区。这与增幅（乘区）和剧变（独立结算）都不同，必须在 `05` 的公式中放在正确位置。

### 5.6 冻结与结晶

**冻结持续时间**【实测】：

```text
冻结时间(秒) = 2 × sqrt(5 × 冻结附着量 + 4) − 4
```

冻结附着量取触发时水与冰附着量的较小值，冻结期间该附着量以固定速率衰减。反复冻结存在递减机制，连续冻结的有效时间逐次缩短。

**结晶护盾吸收量**【实测】：

```text
吸收量 = 等级系数 × 1.5 × (1 + 4.44 × EM / (EM + 1400))
```

结晶护盾对同元素伤害有 2.5 倍吸收效率，护盾存在 15 秒，同时只能存在一个。

**已实现**。四种结晶共用一份 `Eff_Crystallize` 资产：吸收量与元素都随信号传入，元素取**被结晶的那个附着**而不是触发方的岩。「同时只能存在一个」由护盾层的互斥组表达，换元素也一样替换。护盾归**施加者**——原神里结晶产生的是地上的碎片、拾取才获得护盾，本实现直接给施加者，与草原核实体化属于同一类简化。

## 6. 配置结构

### 6.1 元素附着配置

挂在每一个可造成元素伤害的攻击段落上：

```csharp
// 描述单次攻击写入目标的元素附着参数。
public struct ElementApplication
{
    public ElementType Element;      // 附着元素；Anemo/Geo 不写入 Aura，只触发反应
    public GaugeStrength Strength;   // Weak(1U) / Medium(2U) / Strong(4U)
    public IcdPolicy IcdPolicy;      // Shared / Independent / None
    public int IcdGroupId;           // Independent 时用于区分同一天赋内的不同段落
}
```

### 6.2 ICD 策略

| 策略 | 含义 |
| --- | --- |
| `Shared` | 与同天赋其它段落共用一个 ICD 组（默认） |
| `Independent` | 本段落使用 `IcdGroupId` 指定的独立组 |
| `None` | 每次命中必附着 |

### 6.3 反应配置

反应规则以 `ReactionMatrix` 资产集中定义，一行一条反应，包含：触发元素、被触发附着、反应类型、倍率、附着消耗系数、产出效果 `EffectDefinition` 引用。新增反应只应改这张表。

## 7. 运行时结构

```text
ElementSystem（新增 System，实现 ISystemContract）
 ├─ AuraRegistry        : EntityId → ElementAuraSet
 ├─ IcdRegistry         : (SourceId, TalentId, GroupId) → IcdWindow
 ├─ ReactionResolver    : 查 ReactionMatrix，产出 ReactionResult
 └─ ReactionEffects     : 把 ReactionResult 翻译为 EffectRuntime 调用
```

对外接口：

```csharp
public interface IElementSystem : ISystemContract
{
    // 施加一次元素附着并返回本次触发的反应结果；无反应时返回 ReactionResult.None。
    ReactionResult Apply(in ElementApplyRequest request);

    // 只读查询目标当前附着，用于 UI、AI 与配队辅助。
    ElementAuraSnapshot QueryAura(int entityId);
}
```

`Apply` 必须是**同步、无副作用外泄**的：它只修改 Aura 与 ICD 状态并返回结果，由调用方（伤害管线）决定如何使用。剧变伤害与反应产物的施加由伤害管线在结算阶段统一发起，避免在附着阶段产生递归。

**元素系统已落地**，位于 `Assets/Prometheus/Gameplay/ElementSystem/`，已注册进 `PrometheusSystemInstaller`。16 条单测走真实配表覆盖本案验收用例，因此同时校验了表内容与代码行为的一致性。

| 项 | 状态 |
| --- | --- |
| 附着写入、衰减税、衰减速率锁定与刷新规则 | 已完成 |
| ICD 门控（2.5s / 3 次，第 1、4、7… 次生效） | 已完成 |
| ICD 按 `(施加者, 天赋, 段落组)` 分组 | 已完成 |
| 反应矩阵按优先级取唯一反应 | 已完成 |
| 附着消耗系数与触发元素去留 | 已完成 |
| 风与岩不留存附着 | 已完成 |
| 伪元素状态（冻结 / 草原核 / 原激化）的产生与消退 | 已完成，见下 |
| 接入伤害管线 | 已完成，见下 |

**职责边界**：`ElementSystem` 只门控 ICD、维护附着、判定反应命中哪一行。反应的**数值求值**交给 `Gameplay/Combat` 的 `ReactionFormula` 与 `DamageCalculator`（见 [05 第 6.1 节](05_伤害结算公式.md)），反应产物的施加交给伤害管线。因此 `ReactionResult` 只携带命中的配表行与消耗量，不含任何求值结果——这样元素规则与数值公式各自独立可测，元素系统也不必读取施加者的属性面板。

**调用方**：`Gameplay/Combat/DamagePipeline` 在每次伤害结算时调用 `Apply`，把返回的反应行按 `category` 折算成增幅乘区、激化加算或剧变独立伤害，再交给 `DamageCalculator`。五行克制模型已删除。

**伪元素状态机**：三个状态由 `ReactionMatrix` 新增的 `producedAura` 列驱动，时长参数来自新表 `PseudoElementState`，代码里没有按反应标识写死的分支。状态以「剩余秒数按 1/秒 倒数」存储，与真实附着共用同一条衰减与清理路径。

| 状态 | 时长求法 | 附着结算 |
| --- | --- | --- |
| `Frozen` | 第 5.6 节闭式解 `2√(5g+4)−4`，`g` 取触发时双方附着量的较小值 | 把 `g` 合并进状态，水与冰**两侧都扣掉这一份** |
| `Quickened` | 按 `g` 在配表的 5～30 秒区间内线性插值 | 第 5.4 节「不完全消耗双方附着」，两侧都保留 |
| `DendroCore` | 配表固定时长 | 同上，两侧都保留 |

伪元素被命中时消耗是**全有全无**的：状态条存的是剩余秒数而不是附着量 U，按比例扣秒数没有意义。碎冰、超绽放、烈绽放的消耗系数为 1，直接解除状态；超激化与蔓激化为 0，原激化保留，因此一次原激化可以支撑多次激化。

重复触发同一状态取更长的剩余时间，短的那次不会缩短已有状态。

由此**超激化、蔓激化、碎冰、超绽放、烈绽放**五条反应全部可以触发。

**产物落地**：元素系统只广播状态的生灭（写入 / 到期 / 被消耗），把它变成可见后果是 `ReactionProductSystem` 的事——冻结挂上禁止行动的 `Eff_Frozen`，草原核到期时按剧变公式引爆。三条职责线因此仍然各管一段：状态与时钟在元素系统，表现在 Effect 资产，数值在配表与 `DamageCalculator`。

「到期」与「被消耗」必须分开广播：草原核自然到期要引爆，被超绽放消耗则由超绽放自己结算剧变伤害，两者合并会让同一个核打出两笔伤害。
