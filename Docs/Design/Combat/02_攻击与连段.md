# 02 攻击与连段

## 1. 设计目标

原神的攻击手感来自三条规则的组合：**连段有固定节奏且可被打断重置**、**重击是一个独立的资源消耗动作**、**取消窗口由动作而非由输入决定**。复刻的关键不在动作数量，而在窗口时序的精确性。

## 2. 攻击类型

| 类型 | 代码名 | 输入 | 资源消耗 | 基础元素 |
| --- | --- | --- | --- | --- |
| 普通攻击 | NormalAttack | 点击攻击键 | 无 | 物理（草与部分角色为元素） |
| 重击 | ChargedAttack | 长按攻击键 | 体力（法器/弓为蓄力） | 随武器 |
| 下落攻击 | PlungeAttack | 空中按攻击键 | 无 | 物理 |
| 冲刺 | Sprint | 按冲刺键 | 体力 | — |

> 现有实现中的 `SpecialAttackComponent` / `SpecialAttackLogic` 承担的正是重击位；复刻时应更名为 `ChargedAttack` 并补齐下落攻击，见 `90`。

## 3. 五种武器型态

每种武器型态是一套完全独立的动作规格。

### 3.1 单手剑（Sword）

- 普攻 5 段，节奏快，单段倍率低。
- 重击：**消耗体力 20**，独立于连段，可从任意普攻段位接出。
- 下落攻击：低空 / 高空两档伤害 + 落地范围伤害。
- 附着强度：普攻各段 1U。

### 3.2 双手剑（Claymore）

- 普攻 4 段（部分角色 5 段），节奏慢，单段倍率高。
- 重击：**持续消耗体力**（约 40/秒），旋转攻击，松手接一段终结技。达到体力耗尽时强制终结。
- 具备**碎冰能力**，是冻结队的主要解冻手段。
- 硬直等级高，见 `08`。

### 3.3 长柄武器（Polearm）

- 普攻 5～6 段，突刺为主，前摇短。
- 重击：**消耗体力 25**，单次突进刺击。

### 3.4 弓（Bow）

- 普攻：连续射击 2 段。
- 重击：**瞄准模式**。分两档：
  - 未蓄满（< 蓄力时长）：物理伤害；
  - 蓄满：转为角色元素属性的**蓄力箭**，附着 1U。
- 瞄准模式下移动速度大幅降低，视角切换为第一人称瞄准。
- 下落攻击不受武器差异影响。

### 3.5 法器（Catalyst）

- 普攻**全段为角色元素伤害**，不是物理。
- 重击：**消耗体力 50**，单次元素伤害。
- 下落攻击为元素属性。
- 法器角色普攻的 ICD 尤其重要，否则会无限刷反应。

## 4. 连段规则

### 4.1 连段状态机

```text
Idle
 └─(攻击输入)→ N1 ──窗口内再次输入──→ N2 ──→ N3 ──→ … ──→ Nmax
      │                                                      │
      │                                              (播放完毕)│
      └──────────── 窗口超时 / 被打断 ────────────────────────┘
                              ↓
                            Idle（连段重置）
```

### 4.2 三个关键窗口

每一段普攻在时间轴上定义三个窗口，由 `AnimationLine` 上的事件帧标注：

| 窗口 | 含义 |
| --- | --- |
| **命中窗口** | Hitbox 开启到关闭的区间 |
| **连段窗口** | 允许输入下一段的区间。窗口内输入则排队，段落播完立即衔接 |
| **取消窗口** | 允许被其它动作打断的区间。E/Q/闪避/跳跃各有独立的取消起始帧 |

**取消优先级**（高的可打断低的）：

```text
受击 > 元素爆发 > 元素战技 > 闪避/冲刺 > 跳跃 > 重击 > 普通攻击
```

元素爆发与元素战技在**绝大多数帧**都可以取消普攻，这是原神操作流畅度的来源。

### 4.3 连段重置条件

- 连段窗口超时（末段播放完毕后约 1.5 秒无输入）；
- 角色被切换下场；
- 角色被打断进入受击状态；
- 执行了非普攻动作且该动作不允许保留连段计数（闪避允许保留，E/Q 不保留）【待复核】。

### 4.4 攻击速度

`攻击速度` 影响动画播放速率，进而影响连段总时长与 DPS。实现上必须同时缩放：动画播放速度、窗口时间点、Hitbox 开启时长。现有 `PropertyConfig.atkSpeed` 已具备该语义，需扩展到窗口时序。

## 5. 体力（Stamina）

| 行为 | 消耗 |
| --- | --- |
| 冲刺（起步） | 18 |
| 冲刺（持续） | 约 18/秒【待复核】 |
| 单手剑/长柄重击 | 20 / 25 |
| 双手剑重击持续 | 约 40/秒 |
| 法器重击 | 50 |
| 攀爬（持续） | 约 5/秒 |
| 攀爬（冲刺攀爬） | 约 25/秒 |
| 游泳（持续） | 约 4/秒 |
| 游泳（快速游泳） | 约 12/秒 |
| 滑翔（持续） | 约 3.3/秒【待复核】 |

- 上限默认 240，可由「七天神像等级」与部分道具提升。
- 停止消耗后延迟约 1 秒开始恢复，恢复速率约 25/秒【待复核】。
- 体力归零：空中滑翔时下坠、游泳时溺水传送回岸、冲刺时强制停止。
- 体力**全队共享**，不随切人重置。

## 6. 命中判定

### 6.1 Hitbox

现有 `HitboxComponent` 可直接承载。每段攻击配置：

```csharp
// 描述一段攻击携带的战斗数据。注意这里**没有时序字段**，原因见 6.1.1。
public struct AttackSegment
{
    public HitboxShape Shape;             // 球 / 胶囊 / 扇形 / 盒
    public float SkillMultiplier;         // 天赋倍率表索引
    public ElementApplication Element;    // 见 04
    public int StaggerLevel;              // 见 08
    public float HitStopDuration;         // 见 09
    public int MaxTargets;                // 单段最多命中目标数，-1 为不限
}
```

### 6.1.1 时序由动画事件承载，不入段落表

本案早先版本在 `AttackSegment` 里放了 `ActiveStart / ActiveEnd`（归一化动画时间）。**该设计已废弃**：现有 `AnimationLine` 已经用 `EnableHitbox` / `DisableHitbox` 事件驱动命中窗口，两者并存会让「这一段什么时候能打到人」有两个真相来源。

保留动画事件的理由：

- **动画长度一变，表里的归一化时间就要重算，事件不用**；
- 动画事件与段落数值**同为策划维护**——动画师只出动画，事件由策划在 `AnimationLine` 编辑器里配——因此不存在跨岗位同步成本。

段落表因此只承载纯数值，可以完整放进 Luban 配表，没有任何与预制体强相关的字段需要留在 ScriptableObject 里。

### 6.1.3 实现状态

**段落表已落地**：`TbAttackSegment`（`Data/Excel/Datas/Combat/attack_segment.xlsx`），索引在 `Logic/Talent/AttackSegmentTable.cs`。

| 项 | 状态 |
| --- | --- |
| 段落表承载倍率、元素、附着档位、ICD 策略、打断等级、命中上限 | 已完成 |
| 四个天赋 Logic 改为段落驱动 | 已完成 |
| 敌人攻击共用同一张表（`AttackSignalId` 即 `talentId`） | 已完成 |
| 逐级倍率（`TalentMultiplier`） | **未完成**，段落表暂存天赋 1 级倍率，等级缩放仍走统一系数 |
| 命中上限 `maxTargets` | 表已有列，`HitboxComponent` 尚未消费 |
| 击退参数 | 表未建列，见 [承压接缝台账 S-05](../../Arch/LoadBearingSeams.md) |

### 6.1.4 体力

体力池已落地（`Gameplay/StaminaSystem/`），**全队共享、不随切人重置**，因此由系统持有而不是做成逐角色属性。

- 一次性消耗（重击）**全有全无**：不足时一点不扣，与原神「体力不够就放不出重击」一致；
- 持续消耗（冲刺、攀爬、游泳、滑翔）允许扣空并返回实际扣除量，使动作能在体力见底那一刻停下；
- 消耗量随段落走（`TbAttackSegment.staminaCost`），消耗降低读**发起者**的面板。

重击已接上体力；冲刺与移动类消耗属排期第 8 步。

体力上限**全局唯一**：基础 240 + 七天神像累计加成，不随角色变化。05A 里那个逐角色的 `Stamina` 属性位已作废。

**本次重构修掉的两个缺陷**：

1. **普攻各段原先各自独立 ICD**。`NormalAttackHitBinding.ResolveAbilityId` 默认按段生成 `Player.NormalAttack.{n}`，而 ICD 以能力编号分组——实机表现是普攻每一段都附着，反应频率整体偏高。天赋标识改为按「角色 + 动作」推导后，五段共用一条 ICD，与原神一致。
2. **全游戏只有一个附着档位与一个打断等级**。它们此前配在 `DamageOperation` 资产上，而同一份直接伤害 Effect 被普攻、战技、爆发共用。现在随段落走。

### 6.1.2 事件与段落的绑定

一个动画里可以有多个命中窗口（双手剑 N3 的两段命中、大招的多段判定），因此 `EnableHitbox` 必须能指认自己对应哪一行段落数据。

`AnimationLineEvent` 已经带有 `intValue` / `floatValue` / `stringValue` 三个载荷字段，不需要新增机制：

```text
EnableHitbox.intValue = 该动画内的命中窗口序号（0、1、2…）
段落行的键            = (talentId, stageIndex, windowIndex)
```

用**动画内序号**而不是段落表的全局下标：前者是语义键、后者是位置键。表重排或插行不会让已有动画事件指错段落，而策划在动画编辑器里本来就知道「这是本动画的第几个命中窗口」，不必对照表。

### 6.2 单目标单段只命中一次

同一段攻击对同一目标只结算一次，由 `HitRecord` 在段落生命周期内去重。段落切换时清空。

### 6.3 软锁定

攻击时角色自动朝向最近的有效敌人：

- 判定范围：角色前方约 120° 扇形，半径 10 米【待复核】；
- 优先级：屏幕中心偏移 > 距离；
- 锁定只影响**攻击起手瞬间的朝向**，不持续跟随。

## 7. 配置结构

天赋倍率按等级表配置，一张表覆盖一个角色的一个天赋：

```text
TalentMultiplierTable
 ├─ TalentId
 ├─ SegmentName[]        // "一段伤害"、"二段伤害"、"重击伤害"…
 └─ Multipliers[15][]    // 天赋等级 1..15 × 段落数
```

策划维护三样东西，都不接触代码：倍率表、段落表、以及动画事件里的命中窗口时序与序号（见 6.1.1、6.1.2）。
