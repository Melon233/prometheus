# 05A 属性位清单（配表级）

> 本案是 [05 伤害结算公式](05_伤害结算公式.md) 的实现附录，定义全部属性位的 ID、类型、默认值、聚合方式与消费方。
> 配表载体：Luban 管线下的标准 `.xlsx`，规范见 [Docs/ConfigPipeline.md](../../Workflow/ConfigPipeline.md)。本案的三张表尚未建表，建表后位于 `Data/Excel/Datas/Combat/attribute_slot.xlsx`、`enemy_attribute.xlsx`、`talent_multiplier.xlsx`。

## 1. 属性位模型

一个「属性位」是 `PropertyComponent` 上一个可被多来源修改的具名数值槽。全部属性位遵循同一套结构：

```csharp
// 描述一个属性位的静态元数据；运行时值由 PropertyComponent 按聚合方式实时求值。
public readonly struct AttributeSlotDefinition
{
    public readonly AttributeId Id;
    public readonly AttributeAggregation Aggregation; // 见 2 节
    public readonly float DefaultValue;
    public readonly float MinValue, MaxValue;         // 硬性钳制，NaN 表示不限
    public readonly bool AllowNegative;
}
```

修改来源统一通过句柄式 Modifier 施加与移除，沿用现有 `ControlStateModifier` 的模式：

```csharp
// 一份按对象身份增删的属性修改；同一来源可同时持有多个不同属性位的修改。
public sealed class AttributeModifier
{
    public AttributeId Id { get; }
    public AttributeChannel Channel { get; }  // Base / Percent / Flat
    public float Value { get; }
}
```

## 1.1 实现状态

属性位与三通道**已落地**，承载在 `PropertyComponent` / `ModifiableProperty`：

| 项 | 状态 |
| --- | --- |
| 三通道 `(Base + ΣBase) × (1 + ΣBoost) + ΣOffset` | 已完成 |
| `PropertyModifierMode.Base` 供 Effect 写入基础值通道 | 已完成 |
| 主属性、战斗属性、九条伤害加成、五条动作加成 | 已完成 |
| 八条元素抗性与八条抗性削减 | 已完成 |
| 减防、无视防御、受伤降低 | 已完成，由 `DamagePipeline` 读入防御区与抗性区 |
| 反应加成（第 3.5 节的 15 个槽位） | 已完成，由 `ReactionMatrix` 的 `reactionBonusAttr` 列按名字定位 |
| 抗打断等级、霸体 | 属性位已建，**分级硬直判定待 08 落地** |
| `Multiplicative` 与 `Max` 两种聚合 | **未实现**，见下 |

**通道命名与本案的对应**：本案的 `Base` / `Percent` / `Flat` 三通道在代码中是 `Base` / `Boost` / `Offset`。语义完全一致，代码沿用既有命名以免改动全部既有 Effect 资产。

**`Multiplicative` 与 `Max` 两种聚合仍未实现。** 减防与无视防御的独立相乘现在发生在 `DamageCalculator.DefenseMultiplier` 内部——两者作为两个已聚合的标量传入后各乘一次，因此属性位本身仍按加法聚合即可。`Max` 的消费方（抗打断等级）要等 08 的分级硬直落地。属性位已经建好，聚合方式随消费方一起落地，避免先造一个没有调用者的求值分支。

**反应加成的槽位定位**：`ReactionMatrix` 的 `reactionBonusAttr` 列直接写属性位名（如 `VaporizeBonus`），由 `ElementPropertySlots.TryReactionBonus` 解析。列为空表示该反应没有专属加成；非空但拼错会**抛出**而不是当作零——静默归零会让加成永远不生效，且几乎无法反查。

`PropertyComponent` 的属性存储已从「一属性一字段 + 一个 switch 分支」改为按 `PropertyType` 索引的数组：属性位会持续增加，逐字段写法要求每加一个就同步改三处样板，而这三处本可由枚举索引直接得到。

## 2. 聚合方式

| 聚合方式 | 代码名 | 规则 | 适用 |
| --- | --- | --- | --- |
| 三通道 | `ThreeChannel` | `(Base + ΣBase) × (1 + ΣPercent) + ΣFlat` | 生命值、攻击力、防御力 |
| 加法 | `Additive` | `Default + Σ值` | 精通、暴击率、暴击伤害、各类加成 |
| 独立乘 | `Multiplicative` | `Default × Π(1 + 值)` | 减防、无视防御（两者彼此独立相乘） |
| 取最大 | `Max` | `max(Default, 各值)` | 霸体等级、抗打断覆盖 |

**关键约定**：同一属性位内部永远是加法叠加，不同属性位之间才可能相乘。策划判断两个效果是否同乘区，只需看它们是否写入同一个 `AttributeId`。

## 3. 配表：`AttributeSlot`

**表名**：`AttributeSlot`
**用途**：属性位注册表，代码生成 `AttributeId` 枚举的唯一来源。

| 列名 | 类型 | 描述 |
| --- | --- | --- |
| `attributeId` | string | 主键，属性位唯一标识，PascalCase，同时作为生成的 `AttributeId` 枚举成员名 |
| `displayNameKey` | string | 本地化 key，用于面板与词条显示 |
| `category` | AttributeCategory | 分组：`Primary` / `Combat` / `DamageBonus` / `Resistance` / `Reaction` / `Utility` |
| `aggregation` | AttributeAggregation | 聚合方式，见 2 节 |
| `defaultValue` | float | 默认值 |
| `minValue` | float | 下限，`-1e9` 表示不限 |
| `maxValue` | float | 上限，`1e9` 表示不限 |
| `isPercent` | bool | 是否以百分比形式显示 |
| `displayPrecision` | int | 面板显示小数位 |

## 4. 面板求值顺序

### 4.1 攻击力（生命值、防御力同构）

```text
① BaseAtk = 角色等级攻击力(角色成长曲线) + 武器基础攻击力(武器成长曲线)
② PercentSum = Σ 全部 AtkPercent 通道的 Modifier
③ FlatSum = Σ 全部 AtkFlat 通道的 Modifier
④ 最终攻击力 = BaseAtk × (1 + PercentSum) + FlatSum
```

**武器基攻计入 ① 而非 ③**，这是原神数值设计的核心，直接决定攻击力%词条的价值。禁止把武器基攻当作固定值加在 ③。

### 4.2 求值时机

- `PropertyComponent` 缓存求值结果，任一 Modifier 增删时标脏；
- 在 `OnUpdate` 的安全边界统一重算，不在 Modifier 增删的调用栈内重算（避免效果连锁触发时的重入）；
- 现有 `TalentLogic` 的 `projectionDirty` 延迟重建模式即为此模式，沿用。

## 5. `DamageContext` 字段来源映射

`05` 第 7 节定义的 `DamageContext` 每个字段的填充来源，这是伤害管线接线的唯一依据：

| 字段 | 来源 |
| --- | --- |
| `SkillMultiplier` | `TalentMultiplier` 表，按 `talentId + segmentIndex + talentLevel` 查 |
| `Scaling` | `AttackSegment.Scaling`，决定读取 `Atk` / `Hp` / `Def` / `ElementalMastery` |
| `FlatDamage` | `AttackSegment.FlatDamage` |
| `CatalyzeBonus` | `IElementSystem.Apply` 返回的 `ReactionResult.CatalyzeAdd` |
| `DamageBonus` | 按 3.3 的求值式聚合 |
| `IsCritical` | 掷骰：`Random < min(CritRate, 1.0)` |
| `CritDamage` | 施加者 `CritDamage` 属性位 |
| `AmplifyMultiplier` | `ReactionResult.AmplifyMultiplier`，无增幅为 1 |
| `DefenseReduction` | **目标**身上 `DefenseReduction` 位 |
| `DefenseIgnore` | **施加者**身上 `DefenseIgnore` 位 |
| `TargetResistance` | 目标 `{元素}Resistance - {元素}ResistanceReduction` |
| `DamageReduction` | 目标 `DamageReduction` 位 |

注意 `DefenseReduction` 挂在目标身上、`DefenseIgnore` 挂在施加者身上，两者来源不同不可混淆。

## 7. 配表：`TalentMultiplier`

**表名**：`TalentMultiplier`
一行 = 一个天赋的一个段落在全部 15 个等级上的倍率。

| 列名 | 类型 | 描述 |
| --- | --- | --- |
| `talentId` | string | 主键之一，天赋标识 |
