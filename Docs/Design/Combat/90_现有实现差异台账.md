# 90 现有实现差异台账

> 用途：把「当前代码状态」与「1:1 复刻目标」之间的差距逐项列出，作为排期与验收的唯一依据。
> 状态：`保留` / `扩展` / `替换` / `新增`。

## 1. 需要替换的核心模型

这三项是结构性差异，必须替换而非扩展。它们的改动会波及全部战斗代码，应优先排期。

### 1.1 伤害属性模型 —— **已完成**

| 项 | 原状 | 现状 |
| --- | --- | --- |
| 文件 | `Gameplay/EffectSystem/Definitions/DamageAttributes.cs` | 更名 `DamageElements.cs`，只保留动作类别与元素附魔 |
| 模型 | 五行相克，克制关系产生固定 ×1.3 独立乘区 | 元素附着量 + 反应矩阵 |
| 元素枚举 | `DamageAttribute`：Physical/Fire/Water/Lightning/Ice/Grass/Light/Dark | **已删除**，统一用配表生成的 `Prometheus.Config.ElementType` |
| `DamageAttributeRules.GetRelation` | 返回 Neutral/Advantage | **已删除**，由 `ReactionMatrix` 取代 |
| `AdvantageMultiplier = 1.3f` | 常数 | **已删除** |
| `DamageAttributeModifier` | 出伤属性覆盖 | 更名 `ElementInfusionModifier`（元素附魔），机制保留 |

项目里不再有第二个元素枚举：`Light` / `Dark` 无对应物已移除，`Lightning` 并入 `Electro`，`Anemo` / `Geo` 由配表提供且不留存附着。

`EffectSignal` 的 `DamageAttributeRelation` + `DamageAttributeMultiplier` 两个字段被单个 `ReactionId` 取代——信号只携带反应的**身份**，数值影响已经并入 `Value`，挂两份会让下游有两个真相来源。

**资产迁移**：旧 `DamageAttribute.Physical = 0`，新 `ElementType` 里 `0` 是 `None`、`8` 才是 `Physical`，因此 7 个资产的该字段由 `0` 改写为 `8`；取值 1～5（火水雷冰草）在两个枚举中同义同值，未改动。

依据：[04 元素附着与元素反应](04_元素附着与元素反应.md)

### 1.2 能量模型

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 文件 | `EntitySystem/Character/Config/PropertyConfig.cs` | |
| 字段 | `coreEnergyLimit` + `ultEnergyLimit` 双能量 | 单一 `elementalEnergyLimit` |
| 相关信号 | `EffectSignalType.CoreEnergyGain` / `UltEnergyGain` / `CoreEnergyLimitGain` / `UltEnergyLimitGain` | 合并为 `ElementalEnergyGain` / `ElementalEnergyLimitGain` |
| 获取途径 | 未定义 | 元素微粒/晶球拾取，按 `03` 第 4.3 节公式 |

**状态：替换。** 原神只有一种能量（元素能量），由元素微粒补充，受元素充能效率影响。现有「核心能量」概念无对应物。

依据：[03 元素战技与元素爆发](03_元素战技与元素爆发.md) 第 4 节

### 1.3 硬直模型 —— **已完成**

| 项 | 原状 | 现状 |
| --- | --- | --- |
| 判定 | 「伤害打断能力达到韧性值才施加 Stun」的二值模型 | 分级比较：`攻击打断等级 > 目标抗打断等级` |
| 字段语义 | `toughness: float` 作为阈值 | `staggerResistance` 作为等级（沿用字段位，`FormerlySerializedAs` 保留资产数据） |
| 攻击侧 | `DamageOperation.interruptPower` 数值公式 | `DamageOperation.staggerLevel` 整数配置 |
| 霸体 | 无 | `PropertyType.SuperArmor` 非零时**覆盖**抗打断等级 |
| 未打断的事实 | 无 | `StaggerResistedEvent`（表现属排期第 9 步） |

`AttackedLogic` 的动画会话架构与 `replacingPlayback` 连续受击替换按计划保留，未改动。

遗留：每段攻击各自的打断等级需要天赋段落表提供该列（第 5 步）；受击霸体、位移效果与控制抗性递减见 [08](08_受击反馈与硬直.md) 第 2.4 节的状态表。

依据：[08 受击反馈与硬直](08_受击反馈与硬直.md)

## 4. 明确保留的设计

下列现有设计与复刻目标一致，不做改动，新代码应遵循同样模式：

| 设计 | 位置 | 理由 |
| --- | --- | --- |
| `ControlStateModifier` 句柄式贡献 | `PropertyComponent` | 多来源控制状态的正确表达方式，复刻中的冻结、眩晕、定身直接复用 |
| 受击状态跟随动画会话 | `AttackedLogic` | 硬直时长由动画决定而非配置数值，与原神一致 |
| `replacingPlayback` 连续受击替换 | `AttackedLogic` | 正确处理了连续受击不应退出受击状态的边界 |
| `RuntimePermanentEffectProjection` | `Logic/Growth/` | 天赋等级→永久 Effect 的投影模式，元素共鸣与武器被动直接复用 |
| `CasterSnapshot` 式面板快照 | 需新增，但模式同上 | 场外持续效果使用释放瞬间面板 |
| 四动作 Component/Logic 分层 | `Logic/Talent/` | 与原神的普攻/重击/E/Q 分层一致 |
| `EffectDefinition` 承载一切持续效果 | `EffectSystem` | 避免为反应、护盾、共鸣建立平行机制 |

## 5. 架构约束提醒

复刻过程中需持续满足 `Docs/Arch/ArchSpec.md`：

- `ARCH-SYS-005`：`ElementSystem` 与伤害管线的依赖必须构造注入，禁止在 System 实现内使用 `Core.Gameplay`。
- `ARCH-EVT-004`：反应事件、命中信号等载荷类型必须定义在各自领域目录，禁止建集中式事件枚举。
- `ARCH-NAME-001`：`ElementSystem/` 目录名必须与 `ElementSystem` 类名完全一致；`Combat/` 只放库与计算器时不得加 `System` 后缀。
- `ARCH-DATA-001`：战斗 UI 不得成为权威数据源，只读取接口与订阅信号。
- `ARCH-DOC-001`：改动成型系统链路时同步更新本目录下对应文档。
