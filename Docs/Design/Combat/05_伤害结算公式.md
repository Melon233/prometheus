# 05 伤害结算公式

## 1. 设计目标

伤害公式必须做到三件事：**乘区彼此独立**（每一条养成线都有不可替代的价值）、**结算顺序唯一确定**（同样的输入永远得到同样的输出）、**配置可解释**（策划能从一个数看出它落在哪个乘区）。

## 2. 属性定义

### 2.1 基础属性（参与白值/绿值区分）

| 属性 | 代码名 | 说明 |
| --- | --- | --- |
| 生命值 | Hp | 角色等级 + 武器 + 圣遗物 |
| 攻击力 | Atk | **角色基础攻击力 + 武器基础攻击力** 构成白值 |
| 防御力 | Def | |
| 元素精通 | ElementalMastery | 影响全部反应强度 |

**攻击力计算**：

```text
最终攻击力 = (角色基攻 + 武器基攻) × (1 + Σ攻击力%) + Σ攻击力固定值
```

注意武器基攻计入白值并吃攻击力百分比加成，这是原神数值设计的关键点，不可简化。生命值与防御力同理。

### 2.2 战斗属性

| 属性 | 默认值 | 上限 | 说明 |
| --- | --- | --- | --- |
| 暴击率 | 5% | 无硬上限，>100% 按 100% 计 | |
| 暴击伤害 | 50% | 无上限 | |
| 元素充能效率 | 100% | 无上限 | |
| 元素伤害加成 | 0% | 无上限 | 按元素分别计算，八条独立 |
| 物理伤害加成 | 0% | 无上限 | |
| 治疗加成 | 0% | 无上限 | |
| 受治疗加成 | 0% | 无上限 | |
| 护盾强效 | 0% | 无上限 | |
| 冷却缩减 | 0% | 上限 100% | |

### 2.3 敌人属性

| 属性 | 说明 |
| --- | --- |
| 等级 | 参与防御区计算 |
| 基础防御力 | 由等级推导 |
| 元素抗性 | 八条独立，可为负 |
| 抗性削减 | 来自扩散、超导、角色减抗效果 |
| 防御削减 | 独立于抗性，见 4.5 |
| 无视防御 | 独立于防御削减的第二个系数 |

## 3. 主公式

```text
最终伤害 =
    ( 基础伤害 + 激化加算 )
  × ( 1 + 伤害加成 )
  × 暴击区
  × 增幅倍率
  × 防御区
  × 抗性区
  × ( 1 - 减伤 )
```

各乘区依次说明如下。**顺序不可调换**：激化是加算项必须最先并入，增幅是最后一层乘区必须在防御区之前。

## 4. 各乘区定义

### 4.1 基础伤害

```text
基础伤害 = 技能倍率 × 对应属性值 + 固定伤害值
```

- `技能倍率` 来自天赋等级表（1～15 级），按天赋等级查表。
- `对应属性值` 通常是最终攻击力，部分角色按生命值、防御力或元素精通计算。
- `固定伤害值` 用于少数不随面板缩放的技能段落。

一个技能可以有多个段落，每个段落独立走完整条公式。

### 4.2 激化加算

见 `04` 第 5.5 节。激化加算并入基础伤害后，与基础伤害一同吃后续所有乘区。**只有雷、草元素伤害在原激化状态下才享受此项**，其余情况为 0。

### 4.3 伤害加成区

```text
伤害加成 = Σ元素伤害加成 + Σ技能类型加成 + Σ全伤害加成 + Σ特定目标加成
```

全部为加法叠加，构成同一个乘区。例如「火元素伤害加成 46.6%」与「重击伤害提高 30%」在打火元素重击时叠加为 76.6%，而非相乘。

### 4.4 暴击区

```text
暴击区 = 1 + 暴击伤害        （暴击时）
暴击区 = 1                   （未暴击时）
```

暴击判定为每段伤害独立掷骰。展示「期望伤害」时使用 `1 + 暴击率 × 暴击伤害`，但实际结算必须掷骰。

### 4.5 防御区【实测】

```text
防御区 = (攻击者等级 + 100)
       / ( (攻击者等级 + 100)
         + (目标等级 + 100) × (1 - 减防) × (1 - 无视防御) )
```

- `减防` 与 `无视防御` 是两个**独立相乘**的系数，分别来自不同效果，不可合并。
- 同类减防效果内部加法叠加。

### 4.6 抗性区【实测】

抗性区是分段函数，`R` 为目标对该元素的最终抗性（基础抗性 − 全部削减）：

```text
R < 0        →  抗性区 = 1 - R / 2
0 ≤ R < 0.75 →  抗性区 = 1 - R
R ≥ 0.75     →  抗性区 = 1 / (4R + 1)
```

设计意图：负抗收益减半防止无限叠减抗，高抗段做软上限保证高抗敌人不会完全免疫。

### 4.7 增幅倍率

见 `04` 第 5.2 节。无增幅反应时为 1。

### 4.8 减伤区

来自敌人自身的减伤天赋与部分场地效果，与抗性区独立。默认 0。

## 5. 剧变伤害公式

剧变反应**不走主公式**，独立结算：

```text
剧变伤害 = 等级系数 × 反应倍率 × (1 + 16 × EM / (EM + 2000) + 反应加成) × 抗性区
```

不吃攻击力、不吃伤害加成、不能暴击、不吃防御区。抗性区按剧变伤害对应的元素计算。

## 6. 治疗与护盾

**治疗量**：

```text
治疗量 = (治疗倍率 × 对应属性 + 固定值) × (1 + 治疗加成) × (1 + 受治疗加成)
```

**护盾吸收量**：

```text
护盾量 = (护盾倍率 × 对应属性 + 固定值) × (1 + 护盾强效)
```

护盾对**对应元素**伤害有 2.5 倍吸收效率（结晶护盾及元素护盾），对其它伤害 1.0 倍。多层护盾按剩余量从高到低消耗。

**已实现**，见 `Gameplay/ShieldSystem/`。护盾按实体编号存放；**存活时长由施加它的 `EffectDefinition` 决定**，护盾系统本身不持有时钟。被吸收掉的部分不进 `OnTakeDamage`，因此不产生 `HpChanged` 与受击事实——挡住的伤害不是「受到的伤害」。

## 6.1 实现状态

**纯函数结算器已落地**，位于 `Assets/Prometheus/Gameplay/Combat/`：

| 文件 | 内容 |
| --- | --- |
| `DamageContext.cs` | 四类输入结构：伤害、剧变伤害、治疗、护盾 |
| `DamageCalculator.cs` | 主公式、剧变公式、治疗、护盾、暴击区、防御区、抗性区 |
| `ReactionFormula.cs` | 三类反应的元素精通项、增幅倍率、激化加算、结晶护盾 |

21 条单测覆盖本案第 8 节的全部验收用例，外加抗性区分段边界连续性、乘区顺序、负伤害钳制与确定性。全部用例是纯算术，不构造 Entity、不读配表、不碰属性组件。

**已接线**：`DamageOperation.Execute` 现在把一次伤害交给 `DamagePipeline`，由它解析元素、施加附着、取回反应行、聚合各乘区输入，再调用本结算器。五行克制倍率已删除。

`DamagePipeline` 只做**取数与选槽**，不做算术：

| 乘区 | 输入来源 |
| --- | --- |
| 基础伤害 | `EffectValueFormula` 求值结果（倍率与缩放属性写在同一表达式里，管线拿到的是乘积） |
| 伤害加成 | `AllDamageBonus + {元素}DamageBonus + {动作}Bonus`，按元素与动作选槽 |
| 暴击 | `EffectRuntime.NextCriticalRoll()` 掷骰后与 `CritRate` 比较；走运行时自己的确定性随机源，伤害可随种子重放 |
| 增幅 / 激化 / 剧变 | `IElementSystem.Apply` 返回的反应行 + `ReactionFormula` |
| 防御区 | 双方等级；敌人尚无等级组件，一律按 1 级，同级固定折半 |
| 抗性区 | `{元素}Resistance - {元素}ResistanceReduction` |
| 精通项系数 | `ReactionMatrix` 的 `emCoefficient` / `emDenominator` 两列，而不是代码常量——调精通曲线只需改表 |

剧变伤害作为**独立的第二笔伤害**落地：它不吃攻击力、不吃增伤、不能暴击、不吃防御区，也不再触发一次打断，因此不能并进主伤害。

管线自身没有副作用（不扣血、不发信号），16 条单测走真实配表覆盖乘区归属、按元素选槽与四类反应的分类，见 `Gameplay/Combat/Tests/Editor/DamagePipelineTests.cs`。

## 7. 结算管线实现

```csharp
// 承载一次伤害从产生到落地的全部输入，所有乘区按字段分离以便调试与日志。
public struct DamageContext
{
    public int SourceEntityId;
    public int TargetEntityId;
    public float SkillMultiplier;         // 技能倍率
    public float ScalingValue;            // 已解析的缩放属性值，见下
    public float FlatDamage;
    public float CatalyzeBonus;           // 激化加算，无激化时为 0
    public float DamageBonus;             // 已聚合的伤害加成区
    public bool IsCritical;
    public float CritDamage;
    public float AmplifyMultiplier;       // 增幅倍率，无增幅时为 1
    public float DefenseReduction;
    public float DefenseIgnore;
    public float TargetResistance;        // 已扣除全部削减的最终抗性
    public float DamageReduction;
}
```

`DamageCalculator.Evaluate(in DamageContext)` 为**纯函数**，无副作用、可单测。副作用（扣血、触发效果、表现信号）由调用方在拿到结果后执行。这是把伤害公式与战斗流程解耦的唯一手段，也是数值验收得以自动化的前提。

**Context 只携带已解析的数值。** 早先的字段表里写了 `Scaling`（按攻击力/生命值/防御力/精通缩放）却没有对应数值，那样计算器就必须反查属性组件才能求值，也就不纯了。现在改为由接线层解析出 `ScalingValue` 再传入；`ActionType` 与 `Element` 同理——它们用于**选择**加成与抗性，聚合出 `DamageBonus` 与 `TargetResistance` 是接线层的职责，计算器只做算术。

暴击同样由接线层掷骰后以 `IsCritical` 传入：计算器内不得有随机，否则相同输入不再恒得相同输出，数值验收就无法自动化。
