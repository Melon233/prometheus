# 05 养成材料与资源

## 1. 设计目标

材料系统的作用不是「让养成变慢」，而是**让每一天的选择有意义**。它通过三个机制达成：树脂作为共同瓶颈制造取舍、秘境按星期开放制造回访、地方特产不消耗树脂让探索保持价值。

## 2. 原粹树脂

### 2.1 恢复规则

| 项 | 值 |
| --- | --- |
| 上限 | 160 |
| 恢复速率 | 每 **8 分钟** 1 点 |
| 满上限耗时 | 21 小时 20 分 |
| 日产出 | 180 点 |
【实测】

- 超过上限后**不再恢复**，溢出部分直接损失。
- 恢复不受在线状态影响，离线照常。
- **存档存绝对恢复时间戳，不存剩余量**——离线恢复由时间差算出，不需要模拟。这与 POI 刷新用绝对时间是同一条原则。

### 2.2 补充手段

| 手段 | 获得 | 限制 |
| --- | --- | --- |
| 脆弱树脂 | 60 点 | 道具，活动 / 纪行获得 |
| 原石兑换 | 60 点 | 每日次数递增消耗（60/100/100/150…）【待复核】 |
| 浓缩树脂 | 40 树脂 → 1 个 | 上限 5 个，用于秘境双倍掉落 |

浓缩树脂让玩家把零散树脂攒成整块，减少重复挑战次数。它不改变产出效率，只改变操作次数——复刻时不要把它做成额外产出。

## 4. 秘境开放周期

天赋秘境与武器秘境按星期开放，每个秘境三组材料轮转：

| 星期 | 开放组 |
| --- | --- |
| 周一 / 周四 | 第 1 组 |
| 周二 / 周五 | 第 2 组 |
| 周三 / 周六 | 第 3 组 |
| 周日 | **全部开放** |
【实测】

- 天赋秘境与武器秘境**各自独立**按上表轮转，每个地区各有一个。
- 周日全开是刻意的补偿窗口，让错过的玩家能集中补齐。
- 每日刷新时间统一，按服务器时区计算。

## 5. 材料合成

低品阶材料可向上合成，**三换一**：

```text
3 × 品阶N + 摩拉 → 1 × 品阶(N+1)
```

- 适用于元素晶石、天赋书、武器材料、怪物掉落、矿石。
- **不可逆**：高品阶不能拆成低品阶。
- 合成不消耗树脂。

三换一是原神材料经济的基准汇率，全系统统一。复刻时不要为某类材料单独设不同汇率——它会让玩家难以估算「还差多久」。

## 7. 与现有实现的差异

现有实现**完全没有材料与资源系统**：养成消耗不存在，`AddExperience` 直接加经验。需要新增的完整链路：

| 模块 | 说明 |
| --- | --- |
| 材料背包 | 扩展 `BagSystem`，承载材料持有与扣减 |
| 树脂 | 新增；App 段状态，存绝对恢复时间戳 |
| 秘境 | 新增；开放判定、进入、结算、掉落 |
| 掉落 | 新增；按世界等级查 `DropGroup` |
| 合成 | 新增；三换一，走背包扣减 |
| 消耗校验 | 养成各 Logic 在执行前校验并扣除，失败不产生任何副作用 |

**消耗校验必须「先校验、再扣除、后生效」三步原子完成**。现有 `TryEquip` 已经是「先完整验证再创建运行时实例」的模式，材料扣减沿用同一约定：任何一步失败都不留下半成品状态。

### 7.1 当前进度

**已完成**：`IBagSystem.GetQuantity` 持有量查询与 `IBagSystem.CheckCost` 消耗校验（见 `Assets/Prometheus/Gameplay/BagSystem/README.md`）。校验逻辑是纯函数，已有 7 条单测覆盖，含「同一材料重复出现按累计需求判定」这类易漏情况。

**未完成**：权威扣减。背包是服务器权威的，扣减只能由服务器执行，需要先扩 `game.proto` 与 Go 服务端。在此之前养成侧只能做到「校验通过则允许提交」。

因此本节的「先校验、再扣除、后生效」实际分布在两端：**客户端负责先校验**（挡掉明显不成立的操作并给出缺口），**服务器负责扣除与生效的原子性**。客户端校验基于最近一次同步的快照，是建议而非承诺——界面不得因为客户端校验通过就提前播放成功表现。
