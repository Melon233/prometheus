# 90 现有实现差异台账（角色养成）

> 用途：把「当前代码状态」与「1:1 复刻目标」之间的差距逐项列出，作为排期与验收的唯一依据。
> 对照对象：`Assets/Prometheus/Gameplay/EntitySystem/Character/Logic/Growth/` 及其配置与 Component。
> 状态：`保留` / `扩展` / `替换` / `新增`。

## 1. 总体判断

现有养成实现的**架构是对的，模型是错的**。

架构层面已经具备目标模型需要的全部机制：配置 SO 与运行时副本分离、每 Entity 独立的养成实例、`Growth.{EntityId}.{Channel}` 永久 Effect 投影、跨级才重建 Effect 的延迟刷新、`RevisionProperty` 变更通知。这套东西可以原样承载复刻后的养成，不需要重写。

模型层面的分歧集中在一点：**现有实现用「连续曲线」表达成长，原神用「逐级表」表达成长**。角色等级、武器等级、装备词条三处都是 `AnimationCurve` 把归一化经验映射到等级与数值，而原神的每一级都是独立配置的离散值。曲线无法表达「某几级特别贵」「某个段落成长斜率不同」「副词条只在 4 的倍数等级跳一次」这三类需求，因此三处都要换成表。

## 2. 需要替换的核心模型

### 2.1 等级来源：曲线 → 逐级表

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 文件 | `CharaLevelConfig` / `CharaLevelLogic` / `WeaponConfig` / `WeaponLogic` | |
| 模型 | `AnimationCurve` 映射归一化累计经验 → 等级 | `CharacterLevelCurve` / `WeaponLevelCurve` 逐级表 |
| 等级推导 | `Floor(1 + curveProgress × (maxLevel - 1))` | 按表累加 `expToNext` |
| 摩拉消耗 | 不存在 | 表中 `moraToNext` |

**角色侧已完成**（`CharaLevelComponent` 改为逐级表 + 突破状态机）；武器侧仍是曲线，待第 5 步。

**状态：替换。** 依据：[01 第 5.2 节](01_角色等级与突破.md)、[03 第 6.2 节](03_武器系统.md)。

### 2.2 天赋数值：统一系数 → 逐级逐段落表

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 文件 | `TalentConfig` / `TalentLogic` / `TalentGainModifierOperation` | |
| 模型 | `(等级 - 1) × 成长系数`，一个标量乘到全部段落 | 查 `TalentMultiplier[talentId][segmentIndex][level]` |
| 天赋数量 | 4 个可升级（普攻/特攻/技能/大招） | 3 个可升级（普攻含重击与下落）+ 3 个固有天赋 |
| 等级上限 | 配置固定 | 基础 10，受突破阶段约束，命座可至 15 |

**状态：替换数值来源，保留分层结构。** 四个技能 Component 各持 `TalentGrowthState` 的结构保留；`TalentLogic` 的唯一永久 Effect 投影保留。要改的是「等级如何转成数值」。

依据：[02 第 3.3 节](02_天赋与命之座.md)、[Combat/05A 第 7 节](../Combat/05A_属性位清单.md)。

### 2.3 装备词条：静态确定 → 四层随机

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 文件 | `EquipmentConfig` / `EquipmentDefinition` / `EquipmentLogic` / `TierInstance` | |
| 词条来源 | `EquipmentDefinition` 静态指定 | 生成时四层随机：主词条类型、副词条条数、副词条类型、数值档位 |
| 词条成长 | 按等级进度连续缩放到档位最大值 | 主词条按等级查表；副词条**离散累加**，只在 4 的倍数等级变化 |
| 词条类型 | 5 种 | 10 种副词条 + 分部位的主词条池 |
| 部位 | 槽位无类型区分 | 五部位，生之花/死之羽主词条固定 |
| 星级 | 不存在 | 1★–5★ |
| 套装 | 不存在 | 2/4 件套 |

**状态：替换词条模型，保留槽位与投影架构。** 依据：[04 圣遗物系统](04_圣遗物系统.md)。

### 2.4 武器：角色专属 → 可转移实体

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 文件 | `WeaponConfig` / `WeaponComponent` / `WeaponLogic` | |
| 身份 | `WeaponConfig` 同时是 Definition 与成长配置，角色固定一把 | 独立 `WeaponBase` 表，武器实例可在角色间转移 |
| 攻击力 | 用通用词条表达，进 Offset / Boost 通道 | **基础攻击力进 `Atk` 的 Base 通道** |
| 副属性 | 用通用词条表达 | 单独一条，类型固定，按曲线成长 |
| 突破 / 精炼 / 被动 | 不存在 | 全部新增 |

**状态：替换。** 现有 README 已自行提出「后续允许换武器时应拆分出 `WeaponDefinition`」——本案确认该拆分是必须的。

**通道语义的改动最易被忽略**：武器基攻从「词条」变成「Base 通道」后数值不等价，改造时必须重算全部武器配置。依据：[03 第 3.2 节](03_武器系统.md)、[Combat/05A 第 4.1 节](../Combat/05A_属性位清单.md)。

## 4. 明确保留的设计

下列现有设计与复刻目标一致，新代码应遵循同样模式：

| 设计 | 位置 | 理由 |
| --- | --- | --- |
| 配置 SO 只读 + 运行时深拷贝副本 | 全部 Growth Component | 同一配置跨多个 Entity 复用而运行态互相独立，正是多角色养成需要的 |
| `Growth.{EntityId}.{Channel}` 永久 Effect 投影 | 四条养成 Logic | 养成产出统一走 Effect，与战斗侧的属性聚合天然对接 |
| 跨级才重建 Effect | `CharaLevelLogic` / `EquipmentLogic` | 避免同级内经验变化造成属性抖动与无谓重建 |
| `LogicControlRequirement.None` | 四条养成 Logic | 养成不应被眩晕、受击、死亡动作暂停 |
| 延迟到安全边界重建 | `TalentLogic.projectionDirty` | 避免在 Modifier 增删的调用栈内重入 |
| 先完整验证再创建实例 | `EquipmentComponent.TryEquip` | 材料扣减沿用同一约定：失败不留半成品状态 |
| `RevisionProperty` 变更通知 | `EquipmentComponent` | UI 与存档层的统一变更入口 |

## 5. 现有 README 中待确认点的结论

`Growth/README.md` 末尾列出的五个待确认点，本案组给出结论：

| 待确认点 | 结论 |
| --- | --- |
| 档位二元组是否应为「二选一」 | **应拆分**。圣遗物的每条词条只写一个属性位；「固定值」与「百分比」是两个不同属性位（`Atk` Flat 与 `Atk` Percent），不是同一条词条的两个通道 |
| 武器初始等级 | **Lv1**，与角色一致 |
| 主副词条是否共用档位预设 | **不共用**。主词条按等级查表且不随机，副词条按四档随机，数值来源完全不同 |
| 曲线输出是否应约束到 0..1 | **问题消失**。等级改为逐级表后不再有曲线，约束无意义 |
| `WeaponConfig` 是否应拆出 `WeaponDefinition` | **应拆分**，且武器必须可在角色间转移 |

## 6. 架构约束提醒

复刻过程中需持续满足 `Docs/Arch/ArchSpec.md`：

- `ARCH-SYS-005`：新增的养成 System 之间必须构造注入 `I*System` 契约，禁止在 System 实现内使用 `Core.Gameplay`。
- `ARCH-KIT-006`：配表统一经 `Core.Config.Tables` 读取，禁止为养成再建第二份加载入口或缓存。
- `ARCH-LIFE-003`：养成数据属于 Session 段或更长（账号级），**禁止**挂到 World 段——它必须跨场景存活。
- `ARCH-DATA-001`：养成 UI 不得成为权威数据源，只读取接口并提交命令。
- `ARCH-NAME-001`：含 System 的目录名必须与 System 类名完全一致；只含 Logic 与配置的目录不得用 `System` 后缀。
- `ARCH-DOC-001`：改动成型链路时同步更新本目录文档与 `Growth/README.md`。
