# 04 圣遗物系统

## 1. 设计目标

圣遗物是**唯一的随机养成线**，承担整个游戏的长期留存。它的设计要点不在于给多少属性，而在于：**永远不会完美**。主词条随机、副词条种类随机、副词条数值随机、强化时提升哪条副词条也随机——四层随机叠加，使得「再刷一个更好的」永远成立。

复刻时这四层随机一层都不能去掉。去掉任何一层，圣遗物就退化成可预期的第五条确定线，长期留存随之消失。

## 2. 部位

五个部位，每个角色各装备一件：

| 部位 | 主词条 |
| --- | --- |
| 生之花 | **固定为生命值（固定值）** |
| 死之羽 | **固定为攻击力（固定值）** |
| 时之沙 | 随机 |
| 空之杯 | 随机 |
| 理之冠 | 随机 |

生之花与死之羽主词条固定，因此**这两个部位只看副词条**。这是刻意的：它让新手期的圣遗物门槛降低，同时把决策集中在后三个部位。

## 3. 星级与等级

| 星级 | 最高等级 | 初始副词条数 |
| --- | --- | --- |
| 1★ | 4 | 0 |
| 2★ | 4 | 0–1 |
| 3★ | 12 | 1–2 |
| 4★ | 16 | 2–3 |
| 5★ | **20** | **3–4** |
【待复核】

实际养成只用 5★，低星只作为强化材料。

## 4. 词条

### 4.1 主词条

- 每件圣遗物有且仅有 1 条主词条。
- 类型在生成时按**部位对应的概率池**随机（生之花与死之羽除外）。
- 数值随等级线性提升，`Lv0` 为初始值，`Lv20` 为满值，**不随机**。
- 主词条类型不可改变。

各部位的主词条池（5★）：

| 部位 | 可能的主词条 |
| --- | --- |
| 生之花 | 生命值（固定值） |
| 死之羽 | 攻击力（固定值） |
| 时之沙 | 生命值% / 攻击力% / 防御力% / 元素精通 / 元素充能效率 |
| 空之杯 | 生命值% / 攻击力% / 防御力% / 元素精通 / **七系元素伤害加成** / 物理伤害加成 |
| 理之冠 | 生命值% / 攻击力% / 防御力% / 元素精通 / **暴击率** / **暴击伤害** / 治疗加成 |

各类型的出现概率不均等（例如空之杯出元素伤害加成、理之冠出双暴的概率显著低于属性%），具体概率表见 6.2，标记为【待复核】。

### 4.2 副词条

- 5★ 初始 3 或 4 条（4 条的概率较低）。
- 副词条类型从**副词条池**中随机，**不与主词条重复**，四条之间也不重复。
- 每条副词条在生成时从**四个数值档位**中随机取一档。

副词条池（9 种）：

| 副词条 | 对应属性位 |
| --- | --- |
| 生命值（固定值） | `Hp` Flat |
| 生命值% | `Hp` Percent |
| 攻击力（固定值） | `Atk` Flat |
| 攻击力% | `Atk` Percent |
| 防御力（固定值） | `Def` Flat |
| 防御力% | `Def` Percent |
| 元素精通 | `ElementalMastery` |
| 元素充能效率 | `EnergyRecharge` |
| 暴击率 | `CritRate` |
| 暴击伤害 | `CritDamage` |

全部落点都是 [Combat/05A](../Combat/05A_属性位清单.md) 已有的属性位，本案不新增。

### 4.3 强化

- 每 **4 级**触发一次副词条事件：`Lv4 / 8 / 12 / 16 / 20`，共 5 次。
- 若初始只有 3 条副词条，**第一次事件补出第 4 条**；之后每次事件随机选一条已有副词条提升一档。
- 若初始就是 4 条，则 5 次事件全部用于提升。
- 每次提升的档位同样从四档中随机。

因此一件 5★ 圣遗物满级后：

```text
初始 4 条 → 5 次提升 → 单条最多被提升 5 次
初始 3 条 → 补 1 条 + 4 次提升 → 单条最多被提升 4 次
```

**初始 4 条副词条的圣遗物强度上限更高**，这是判断一件圣遗物是否值得强化的第一标准。

### 4.4 强化消耗

- **圣遗物经验**：由其它圣遗物转化，按星级与等级折算；被吞噬的圣遗物已投入的经验部分返还【待复核】。
- **摩拉**：按目标等级递增。

## 5. 套装效果

- 每件圣遗物属于一个套装。
- 装备**同套装 2 件**触发 2 件套效果；**同套装 4 件**同时触发 2 件套与 4 件套效果。
- 可以 `2+2` 混搭两个套装的 2 件套效果。
- 套装效果由 `EffectDefinition` 承载，队伍编成或装备变更时重算。

常见的 2 件套效果是单一属性加成（攻击力% 18%、元素伤害加成 15%、治疗加成 15% 等），4 件套是机制性效果。

## 7. 生成算法

一件圣遗物的生成必须严格按序执行，顺序错了会改变概率分布：

```text
① 确定套装与部位（由掉落来源决定）
② 确定星级（由掉落来源决定）
③ 按 ArtifactMainAffixPool[部位] 的权重抽主词条类型
④ 抽初始副词条条数（5★：3 条或 4 条，按概率）
⑤ 循环抽副词条类型：
   └─ 从 ArtifactSubAffix[星级] 中按权重抽，排除主词条类型与已抽中的类型
⑥ 为每条副词条从 tier1..tier4 中等概率抽一档
⑦ 等级置 0，主词条取 ArtifactMainAffixValue[星级][类型][0]
```

强化到 `4/8/12/16/20` 时：

```text
若当前副词条数 < 4 → 按 ⑤⑥ 补一条
否则              → 等概率选一条已有副词条，从 tier1..tier4 等概率抽一档累加
```

**排除逻辑（⑤ 的第二行）是最容易漏的**：副词条不能与主词条同类型，也不能彼此重复。漏掉会导致出现「攻击力% ×2」这种非法圣遗物。

## 8. 与现有实现的差异

现有 `EquipmentComponent` / `EquipmentLogic` 已经具备五槽位、主词条唯一、副词条数量上限、按等级进度缩放词条、`Growth.{EntityId}.Equipment.Tiers` 永久 Effect 投影——**骨架与圣遗物高度吻合**，是养成模块里最接近目标的一条线。

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 词条类型 | 5 种（攻防双暴生命） | 10 种副词条 + 分部位的主词条池 |
| 词条数值 | 档位预设 × 等级进度**连续缩放** | 主词条按等级查表；副词条**离散累加**，只在 4 的倍数等级变化 |
| 随机性 | **无**，词条由 `EquipmentDefinition` 静态指定 | 四层随机：主词条、副词条条数、副词条类型、数值档位 |
| 部位语义 | 槽位无类型区分 | 五部位，生之花/死之羽主词条固定 |
| 星级 | **不存在** | 1★–5★，决定等级上限与副词条数 |
| 套装 | **不存在** | 2/4 件套 `EffectDefinition` |
| 等级上限 | 配置 20 | 按星级，5★ 为 20 |
| 强化消耗 | **不存在** | 圣遗物经验 + 摩拉 |

**副词条的成长方式必须从连续改为离散**。现有实现让词条值随经验进度连续缩放（README 明确写了「同一级内增加经验不会让战斗属性连续漂移」，但级内仍按离散等级进度取值）；圣遗物是「只在 4 的倍数等级跳一次，且跳哪条随机」。这是模型差异，不是参数差异。

保留：`TierInstance` 的运行时副本隔离、按 `PropertyType + Modifier 通道` 汇总、唯一永久 Effect 投影、`RevisionProperty` 变更通知。

现有 README 自己提出的两个待确认点，本案给出结论：

- **主副词条应使用不同的数值表**：目标模型里主词条按等级查表、副词条按四档随机，两者数值来源完全不同，不能共用一套档位预设。
- **档位二元组 `(maximumOffset, maximumCoefficient)` 应改为单值 + 属性位**：圣遗物的每条词条只写一个属性位，「固定值」与「百分比」是两个不同的属性位（`Atk` Flat 与 `Atk` Percent），不是同一条词条的两个通道。
