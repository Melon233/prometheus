# 晨风原开局区：布局数据与生成链路

开局区（512 × 512 m）的场景美术以一份布局数据为唯一数据源。地形高度图、俯视布局图、城镇地块和自动校验都由它生成；后续的 Unity 白盒地形与建筑方块也读取同一份数据，保证概念图和白盒一致。

## 文件

| 路径 | 作用 |
|---|---|
| `Assets/Art/OpeningArea/Layout/layout.json` | 布局数据（手写）：海岸线、基础高度场控制点、悬崖带、岩脊、山脊、高地、平地、河流、溪沟、道路、城镇、POI、主路线、镜头、林地 |
| `Tools/OpeningArea/build_layout.py` | 生成器（需要 numpy，用 Blender 自带的 Python 运行） |
| `Assets/Art/OpeningArea/Layout/Generated/heightmap.r16` | 513 × 513 高度图，小端 uint16，行 = y（向北），列 = x（向东），按 `height_min..height_max` 线性编码 |
| `Generated/heightmap_meta.json` | 高度图编码信息 |
| `Generated/layout_map.png` | 全区彩色俯视图，每米 2 像素，北在上 |
| `Generated/town_map.png` | 城镇特写，每米 6 像素 |
| `Generated/layout_resolved.json` | 解析结果：POI 地面高度与路线里程、镜头、城镇地块（多边形、层数、高度、基座高度）、主路线剖面、道路坡度 |
| `Generated/report.json` | 自动校验结果 |

运行：

```bash
"C:/Program Files/Blender Foundation/Blender 5.2/5.2/python/bin/python.exe" Tools/OpeningArea/build_layout.py
```

## 坐标约定

- 单位为米。`x` 向东、`y` 向北，对应 Unity 的 `x`、`z`；高度为绝对海拔，海平面 0 m。
- 角色面向 -Y 是 Blender 的约定，与本数据无关；本数据只描述世界布局。

## 地形合成顺序

后一步会覆盖前一步，顺序决定了交汇处以谁为准。

1. **两套基础高度场**：`lower`（悬崖带以南的海岸低地）和 `upper`（其余区域），都由控制点高斯加权插值，再叠加确定性值噪声。
2. **悬崖带**：按 `heights` 沿线指定崖高，低地一侧在 `correction_falloff` 内修正到 `upper - 崖高`，再以 `half_width` 的陡坡切换两套场。教学崖（C）就是其中崖高最低的一段。
3. **岩脊**：沿折线叠加平顶、陡侧的凸起，用来封住绕行路线。
4. **神像高地**：椭圆平顶加陡峭边缘，与周边取较高值。
5. **东侧山脊**和**北侧边界**的抬升。
6. **平地**：出生空地、战斗空地、神像平台。
7. **海岸**：沙滩段缓降；`cliff_coasts` 矩形内为海崖，崖下直接是深水。两者在矩形边界 8 m 内渐变。
8. **河流**：U 形河床，河岸压到略高于水面。
9. **道路**：按等级施工（小径 → 隘口 → 主路），交汇处以高等级道路为准。路面高度由控制点沿弧长插值。道路在河流之后施工，避免河岸下切挖低桥头。桥梁不改地形。
10. **溪沟**：相对两岸下切，在 B 点附近收窄到 2.2 m。
11. **城镇**：城墙矩形内先按台地中心做平滑底面，再压平各台地（1.5 m 过渡即挡土墙），最后压广场和街道。

## 城镇地块

1. 先放 `landmark_buildings`（钟楼、教堂、骑士团总部、冒险家协会、酒馆等），它们的位置是手写的。
2. 沿每条街（阶梯除外）两侧连续排门面房：按弧长推进，放不下就逐级缩小面宽和进深，仍放不下则前进 1 m 再试。
3. 广场外缘一圈门面朝向广场的建筑。
4. 沿城墙内侧留空边界排一圈背靠城墙的房子。
5. 剩余空地随机补少量后排小屋，其余作为院落。

参数在 `town.filler` 中，随机数种子来自 `seed`，同一份数据每次生成结果相同。

## 自动校验

可行走格子的定义：坡度不超过 40°、不是深水（海或河水深超过 1.2 m）、不在城墙或建筑上。桥面可走。溪沟按设计视为需要跳过或攀爬上岸，不算可直接行走。

| 类别 | 检查内容 |
|---|---|
| 连通性门槛 | 出生区与崖下不连通（必须跳溪）；崖下与崖上不连通（必须攀爬）；荆棘未烧时到不了神像高地；烧掉后 G、H、I、J 和城镇广场都可达 |
| 地形 | 教学崖高 5～6 m 且崖面坡度大于 50°；悬崖带其余段不低于 7 m；战斗空地平整；主路线没有非预期跌落；东侧山脊不可行走 |
| 道路 | 主路 ≤ 12°，小径 ≤ 20°，隘口 ≤ 18°，城镇街道 ≤ 10°，阶梯 ≤ 35° |
| 视线 | C 崖顶到 F 之间能看到神像；神像全景机位和下坡主路能看到钟楼；进南门第一眼能看到广场和钟楼（视线计入地形和建筑，被看的目标建筑本身不算遮挡） |

修改布局数据后重新运行生成器，所有检查会重算。任何一项失败都应先修数据，再进入下一阶段。

## Unity 白盒

生成器额外输出两份给 Unity 的数据：

| 文件 | 内容 |
|---|---|
| `Generated/surface.bytes` | 513 × 513 地表类别（每格 1 字节）：0 草地、1 岩石、2 道路、3 沙滩、4 城镇地面、5 林地、6 石板街道、7 水下 |
| `Generated/whitebox.json` | JsonUtility 可直接解析：水体折线（河流水位、溪沟水位）、桥、城墙与城门、建筑（四角、基座、高度、功能）、道具、树木占位、POI、镜头（含眼高）、主路线采样 |

构建器 `Assets/Art/OpeningArea/Editor/OpeningAreaWhiteboxBuilder.cs`：

- `Tools/Opening Area/Build Whitebox`：以叠加方式打开（或新建）`Assets/Art/OpeningArea/OpeningArea_Whitebox.unity`，重建根节点 `OpeningArea_Whitebox` 下的全部内容并保存场景。不会改动编辑器里已打开的其它场景。
- `Tools/Opening Area/Render Views`：用 `Cameras` 下的机位各渲染一张 1600 × 900 截图到 `Whitebox/Renders/`。渲染时临时隐藏其它已加载场景。代码调用 `RenderViews(false)` 可以隐藏标记与路线，输出 `_clean` 版本。

白盒内容：

| 节点 | 内容 |
|---|---|
| `Terrain` | 由 `heightmap.r16` 生成，位置 y = `height_min`；颜色图由地表类别着色，叠加 4 m 细网格和 32 m 粗网格，用来目测尺寸；材质复用 `Stylized/GenshinTerrain` |
| `Water` | 海平面（0 m）和河、溪的水面带 |
| `Bridges` | 桥面、栏杆、桥墩 |
| `TownWall` | 每 8 m 一段、按地形自适应墙基的城墙，角楼，南门门楼（开），北门与水门（关闭，画成门板） |
| `Buildings` | 建筑体块：墙体向下埋 3 m，坡屋顶沿长边；功能建筑为蓝色，可进入的冒险家协会和酒馆为黄色；钟楼带四棱锥尖顶 |
| `Props` | 神像、锚点、宝箱、采集点为统一的青色（可交互物）；荆棘丛垂直于隘口道路摆放；木桩、营地、火盆、马车、风车、路牌 |
| `Trees` | 树木占位按 128 m 区块合并成网格（树干、树冠各一份） |
| `Markers` | A～J 区域标杆和名称、可选点、NPC（GirlBase 素体，面朝玩家来的方向）、复活点、`PlayerStart`、贴地的主路线 |
| `Cameras` | 四个过场机位和一个全区鸟瞰机位（相机组件默认关闭） |
| `Lighting` | 西南来光的太阳。关键视角大多朝北、东北看，因此看到的是受光面 |

构建结束时会核对地形采样高度与 POI 地面高度，最大误差写进日志，误差来自 16 位量化和插值。

改动布局的流程：修改 `layout.json` → 运行 Python 生成器（36 项校验必须全部通过）→ `Build Whitebox` → `Render Views`。
