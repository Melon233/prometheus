## 跨模块约定

### 数值置信度标记

正文中的数值带如下标记，**未经确认的数值禁止直接实装**：

- **【实测】**：社区通过大量实测反推、已被广泛验证的公式或常数，可直接实装。
- **【待复核】**：结构确定但具体数值需在实装前用原神实机再次确认。
- **【自定】**：原神未公开且无法实测的部分，由本项目自行定义，需在评审中确认。

### 配表

全部配表走 Luban：策划在 `Data/Excel/` 维护 `.xlsx`，导表生成 C# 代码到 `Assets/Gen/Config`、二进制数据到 `Assets/BundleResources/Table`。目录职责、表头规范、类型写法与新增表的步骤见 [Docs/Workflow/ConfigPipeline.md](../Workflow/ConfigPipeline.md)，策划案不重复定义。

导表入口：Unity 菜单 `Prometheus/Luban/导出配表`，或 `Tools/Luban/gen.bat`。

### 附录编号

带 `A` 后缀的是**配表级附录**（如 `04A`、`05A`）：把对应主案的规则落成可直接填写、可被导表工具消费的表结构。主案定义「规则是什么」，附录定义「这条规则的数据长什么样」。两者冲突时以主案为准，并同步修正附录。

编号 `90` 固定为该模块的**现有实现差异台账**：代码现状到目标模型的逐项改造清单。

### 与架构规范的关系

策划案描述玩法规则，不规定代码结构。实现时的分层、依赖方向、Kit 与 System 边界以 [Docs/Arch/ArchSpec.md](../Arch/ArchSpec.md) 为准；两者冲突时，先确认是规则表达问题还是架构约束问题，再决定改哪一边（见 `ARCH-META-001`）。
