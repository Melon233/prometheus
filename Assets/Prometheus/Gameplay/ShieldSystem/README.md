# ShieldSystem

护盾的唯一权威：登记护盾层、按规则吸收伤害、在护盾耗尽时移除它。

## 边界

本系统只管「有多少、挡多少、什么时候碎」。另外两件事各有归属：

| 事 | 归属 | 理由 |
| --- | --- | --- |
| 护盾能存活多久 | 施加它的 `EffectDefinition` | 时长是配置，Effect 的 duration 与实例资源已经能完整表达它 |
| 护盾量怎么算出来 | `DamageCalculator.EvaluateShield` / 反应矩阵 | 数值求值是纯函数的事 |

护盾按实体编号存放而不是做成 Entity 组件，与 `IElementSystem` 的附着一致：新增一种会吃护盾的实体不需要改动它的组装流程。

## 吸收规则

按 [05 第 6 节](../../../../Docs/Design/Combat/05_伤害结算公式.md)：

- 元素亲和护盾对**同元素**伤害按 **2.5 倍**效率吸收，对其它伤害 1.0 倍。名义量 1000 的火护盾能挡下 2500 点火伤，但只能挡下 1000 点其它伤害。
- 扣的是**名义量**：同元素时挡下 2.5 点只消耗 1 点护盾。
- 多层护盾按**剩余量从高到低**消耗。厚的先挡，这样一次大伤害不会把多层薄盾一起打碎。
- 各层按自己的元素亲和独立计算效率，不共享。

被护盾吸收掉的部分不进 `PropertyComponent.OnTakeDamage`，因此也不产生 `HpChanged` 与受击事实——挡住的伤害不是「受到的伤害」。

## 互斥组

`ShieldLayer.GroupKey` 表达「同组护盾同时只能存在一层，新的替换旧的」。结晶护盾填 `Crystallize`，从而实现 04 第 5.6 节的「同时只能存在一个」——**换元素也一样替换**，因为互斥是按组而不是按元素。

## 句柄式持有

`AddLayer` 返回的 `ShieldLayer` 是身份句柄，`ShieldOperation` 通过 `EffectInstance.SetResource` 持有它，Effect 结束时精确撤下自己那一层，不会误伤其他来源提供的同元素护盾。

移除一层已经被打碎或被同组替换掉的护盾是安全的空操作。

## 结晶护盾的链路

一次结晶反应要走完四段，每段各归其位：

1. `DamagePipeline` 按反应行算出吸收量，写进 `DamageResolution.ProductValue`，元素取**被结晶的那个附着**（不是触发方的岩）；
2. `DamageOperation` 把值与元素装进一条子信号，施加 `ProductEffectId` 指向的产物 Effect，**目标是施加者**；
3. `Eff_Crystallize` 资产提供 15 秒时长，其 `ShieldOperation` 从信号读值与元素，再按施加者面板乘一次护盾强效；
4. 本系统按上面的规则吸收。

四种结晶共用一份资产：元素与吸收量都随信号传入。分成四份反而会让「同时只能存在一个」需要跨定义互斥，而 Effect 的叠加键做不到跨定义。

## 尚未实现

- **破盾事实**。护盾被打碎时没有发出任何事件，09 要的破盾音效与 VFX、血条护盾段都还没有接入点。
- **岩元素共鸣**「护盾状态下伤害 +15%」之类依赖「当前是否有护盾」的效果，需要一个可被 Effect 条件读取的查询入口。
- **结晶碎片**。原神里结晶产生的是地上的碎片，拾取才获得护盾；本实现直接把护盾给施加者，与草原核实体化属于同一类简化。
