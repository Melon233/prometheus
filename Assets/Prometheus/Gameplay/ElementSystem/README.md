# ElementSystem

元素附着与反应的唯一权威。按 `Docs/Design/Combat/04` 实现，配表见 `04A`。

## 职责边界

它只做三件事：**门控 ICD、维护附着、判定反应命中哪一行**。

它**不做**的事同样重要：

- 不结算任何伤害。反应的数值求值交给 `Gameplay/Combat` 的 `ReactionFormula` 与 `DamageCalculator` 两个纯函数。
- 不读取任何属性面板。元素精通、反应加成、等级系数都是伤害管线的输入，不是元素系统的。
- 不施加任何效果。剧变伤害与反应产物由伤害管线在结算阶段统一发起——在附着阶段施加会产生递归。

因此 `ReactionResult` 只携带命中的配表行与本次消耗量，不含任何求值结果。元素规则与数值公式各自独立可测。

## 组成

| 文件 | 职责 |
| --- | --- |
| `IElementSystem.cs` | 契约、`ElementApplyRequest`、`ElementAuraSnapshot` |
| `ElementSystem.cs` | System 实现，持有三个注册表并驱动衰减 |
| `ElementAuraSet.cs` | 一个目标的全部附着；纯数据，时间由 dt 传入 |
| `IcdRegistry.cs` | ICD 窗口；时间由绝对秒数传入 |
| `ReactionMatrixIndex.cs` | 反应矩阵索引与 `ReactionResult` |

三个数据结构都不认识 Unity 时钟，因此可以脱离引擎逐条验证。

## 附着规则

- **衰减税**：标称 1U 实际写入 0.8U，见 `TbGaugeStrength`。
- **衰减速率在写入时按标称值锁定**，之后不随剩余量改变。
- **同元素刷新**取 `max(当前剩余, 新写入)`，但速率**总是**取新一次施加对应的值——即使新施加量更小也会重设。
- **风与岩不留存附着**：它们只作为反应触发方。

## ICD

默认 2.5 秒 / 3 次，生效序列是第 1、4、7… 次。分组按 `(施加者, 天赋, 段落组)` 而非按元素，因此同一角色的普攻与战技是两条独立的 ICD。

`RegisterHit` 把判定与推进合成一个方法。拆成「查询 + 推进」两步会让调用方有机会只查不推，从而把窗口计数与实际命中次数解耦——这类错误在实机里表现为反应频率忽高忽低，极难排查。

计数在 `1..hitCount` 之间**一步环绕**：第 3 次之后直接回到 1 而不是先归零再等下一次递增。归零写法会让第 4 次落在 1 却仍被判为不附着，实测就是这么错的。

## 反应判定

单次攻击**只触发一种反应**。目标身上有多个可反应附着时按 `priority` 降序取第一条——带水与雷的目标被火命中时优先蒸发（100）而非超载（90）。

候选行在建索引时已按优先级排好，每次查询不重复排序。

## 尚未实现

- **伪元素状态**（`Frozen` / `DendroCore` / `Quickened`）的产生与消退。`ElementAuraSet.ApplyState` 已就位，但冻结时长公式、草原核实体与原激化状态机尚未接。
- **结晶护盾**。`Eff_Crystallize_*` 需要一套护盾吸收机制（伤害先扣盾再扣血），项目里还没有。`ReactionFormula.CrystallizeShield` 已就位，缺的是承载它的运行时。
- **草原核实体化**。原神中草原核是独立的世界实体（有位置、上限五个、延时自爆、可被别的目标引爆），本案把它建模为目标身上的一层状态，丢失了位置无关性与延时自爆。偏差的具体表现见 [04A 第 5 节](../../../../Docs/Design/Combat/04A_反应矩阵配表.md)。
- **反复冻结递减**。04 第 5.6 节提到「连续冻结的有效时间逐次缩短」但未给公式，因此没有实现——没有公式就不猜。

## 伪元素状态机

三个状态由 `ReactionMatrix` 的 `producedAura` 列声明、由 `PseudoElementState` 表给出时长，代码里没有按 `reactionId` 写死的分支。

状态以「剩余秒数按 1/秒 倒数」存储，与真实附着共用同一条衰减与清理路径，不必为状态另建生命周期。代价是 `ElementAura.Gauge` 对状态条存的是秒而不是 U，因此读它之前必须先看 `IsState`。

冻结是唯一有特殊附着结算的反应：它把水与冰中较小的一份合并进状态，两侧都扣掉这一份。绽放与原激化按 04 第 5.4 节不消耗双方附着。这个差异由配表的 `durationMode` 区分，不是按反应名写死。

伪元素被命中时消耗是**全有全无**的：按比例扣「剩余秒数」没有意义。

## 调用方

`Gameplay/Combat/DamagePipeline` 在每次伤害结算时调用 `Apply`，并把返回的反应行交给 `ReactionFormula` 与 `DamageCalculator` 求值。本系统不参与求值，因此不读取任何属性面板。
