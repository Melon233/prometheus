# Feature Spec 模板

> 使用方式：每个 feature 复制一份下表填写。所有字段面向「策划以外的人 / AI」消费，写完后应能被开发、美术、TA、测试直接按字段取值，无需二次沟通。

---

## Feature 基本信息

| 字段 | 填写内容 |
|---|---|
| **Feature ID / 名称** | 例：`CMB-001 三段连击` |
| **所属系统** | 例：战斗系统 / 移动系统 |
| **版本** | 例：v0.1 |
| **负责人** | 主策划 / 系统策划 |
| **状态** | 草稿 / 评审中 / 已通过 / 变更中 |

---

## 一句话目标

> （一句话说清：这个 feature 解决什么问题、给玩家什么体验）

例：让玩家通过连续普攻打出三段递增伤害，形成最基础的战斗节奏。

---

## 触发条件

> （何时、何条件下此 feature 生效；列出所有触发入口）

| 触发方式 | 条件描述 |
|---|---|
| 按键 | 玩家在非硬直状态连续按下攻击键 |
| 自动 | 无 |
| 其他 | 目标处于可攻击范围内 |

---

## 详细规则

> （分步骤、无歧义描述。禁止模糊词：大概 / 适当 / 流畅 / 手感好 / 炫酷 / 差不多）

1. 第 1 段：前摇 0.1s，造成伤害 10，后摇 0.2s。
2. 第 2 段：在第 1 段后摇结束后的 **0.15s 窗口内** 再次按下攻击键才触发，否则回退到第 1 段。
3. 第 3 段：同理在第 2 段后摇后的 0.15s 窗口内触发；第 3 段造成伤害 20 并附带击退 1m。
4. 任意段可被闪避 / 受击打断，打断后连击计数清零。

---

## 数值表

> （初始值 + 可调范围。区分「设计值」与「可接受范围」，程序应做成配置项）

| 参数 | 设计值 | 可调范围 | 单位 |
|---|---|---|---|
| 第 1 段伤害 | 10 | 5–20 | 点 |
| 第 2 段伤害 | 15 | 8–25 | 点 |
| 第 3 段伤害 | 20 | 10–35 | 点 |
| 连击窗口 | 0.15 | 0.1–0.3 | 秒 |
| 第 3 段击退距离 | 1 | 0.5–2 | 米 |

---

## 状态与边界

> （异常、冲突优先级、空输入、极限情况）

- 连击期间受到控制（眩晕 / 冰冻）→ 立即中断，计数清零。
- 目标死亡 → 第 3 段不结算击退，伤害照常。
- 攻击键与技能键同时按下 → 技能优先，普攻连击暂停而非清零（待确认）。
- 无目标时按键 → 播放空挥动画，不进连击计数。

---

## 验收标准（AC）

> （一律 Given / When / Then 写法，可被测试直接断言）

1. `Given` 玩家满血站在目标旁，`When` 连续按下攻击键 3 次（间隔 <0.15s），`Then` 三段连击在 0.8s 内完整播放，总伤害 = 10+15+20。
2. `Given` 玩家在第 1 段后摇结束后 0.2s 才按第 2 次，`When` 按下，`Then` 重新播放第 1 段，不进入第 2 段。
3. `Given` 连击第 2 段进行中，`When` 玩家按下闪避键，`Then` 连击中断、计数清零、闪避动画播放。
4. `Given` 目标血量为 5，`When` 第 1 段命中，`Then` 目标死亡，后续连击段伤害照常结算但击退不生效。

## 美术需求

> （带规格，不写「炫酷」。TA 据此做性能预算）

| 资源 | 规格 |
|---|---|
| 三段攻击动画 | 各段循环/单次，总时长 ≤1.2s，人形骨骼 |
| 命中特效 | 单次 ≤0.3s，最大粒子数 ≤200，遵循战圈色板 |
| 攻击音效 | 3 段各一，格式 WAV 44.1kHz |
| UI 连击提示 | 可选，不阻断战斗 |

---

## 风险与待定项

- 攻击键 / 技能键冲突优先级尚未定死，需数值策划确认。
- 第 3 段击退是否会穿墙，需关卡组确认。
