# 评审门清单

> 每道门 = AI 预审 + 人工裁决。通过 / 驳回 / 修改的按钮永远在人的手里。AI 只出「提案 + 预审报告」。

---

## G0 · 立项门

| 项目 | 内容 |
|---|---|
| 触发时机 | 阶段 0 立项案完成后 |
| 检查内容 | 立项案是否有明确的核心玩法、目标用户、技术可行性、里程碑 |
| AI 预审 | 生成《立项风险评估》：范围是否过大、是否有未定关键项 |
| 通过标准 | 主策划 + PM 一致确认「方向可继续细化」 |
| 人工动作 | 批准 / 驳回（打回补范围）/ 修改 |
| 驳回回退 | 回阶段 0 |

---

## G1 · 策划评审门（核心门）

| 项目 | 内容 |
|---|---|
| 触发时机 | 阶段 1 战斗系统策划案初稿完成后 |
| 检查内容 | 一致性 / 完整性 / 歧义 / 依赖闭环（四查） |
| AI 预审 | Web 检索竞品 + 自主评审，产出《评审报告》 |
| 自动 lint | 扫描模糊词黑名单：`大概/适当/流畅/手感好/炫酷/差不多` → 标红 |
| 通过标准 | 每个 feature 均含完整字段 + 可观测 AC；无未解决歧义 |
| 人工动作 | 主策划裁决 + 开发/美术/测试代表确认「可读性」 |
| 驳回回退 | 回阶段 1 继续润色 |

---

## G2 · 契约确认门

| 项目 | 内容 |
|---|---|
| 触发时机 | 阶段 2 拆解完成后、阶段 3 并行开工前 |
| 检查内容 | TA 产出的「接口契约 + 资源规格契约」是否无歧义、可执行 |
| AI 预审 | 检查契约字段完整性、命名唯一性、与 Feature Spec 的引用一致性 |
| 通过标准 | PM / 主策划确认契约定稿，三线方可并行 |
| 人工动作 | 批准 / 驳回（改契约）/ 修改 |
| 驳回回退 | 回阶段 2 重抽契约 |

---

## G3 · 集成门

| 项目 | 内容 |
|---|---|
| 触发时机 | 阶段 4 集成完成后 |
| 检查内容 | 资源规范 + 功能可运行 |
| AI 预审 | 自动化规范校验（尺寸/面数/格式/命名）+ 编译/运行检查 |
| 通过标准 | 所有占位资源已替换为正式资源；无规范违规；核心功能可运行 |
| 人工动作 | TA 审资源 + 开发确认功能 |
| 驳回回退 | 回阶段 3（对应组修复） |

---

## G4 · 测试门

| 项目 | 内容 |
|---|---|
| 触发时机 | 阶段 5 测试完成后 |
| 检查内容 | 所有 feature 的 AC 是否通过 |
| AI 预审 | 自动化用例 + 探索性测试报告 |
| 通过标准 | AC 全绿；严重/致命 bug 清零；遗留 bug 有明确责任人与排期 |
| 人工动作 | 测试 + PM 共同裁决是否放行 |
| 驳回回退 | 缺陷回环：bug → 修复 → 复测 |

---

## G5 · 验收门

| 项目 | 内容 |
|---|---|
| 触发时机 | 阶段 6 复盘前 |
| 检查内容 | 对照里程碑是否达成 v0.1 目标 |
| AI 预审 | 汇总全链路追踪数据（feature→ticket→code→asset→test→bug） |
| 通过标准 | 里程碑范围全部交付，无未关闭的阻塞项 |
| 人工动作 | PM 批准发布；复盘会沉淀回流 |
| 驳回回退 | 回对应阶段 |

---

## 门禁总览

| 门 | 阶段 | 核心裁决人 | AI 产出物 |
|---|---|---|---|
| G0 立项门 | 0→1 | 主策划 + PM | 立项风险评估 |
| G1 策划评审门 | 1→2 | 主策划 + 各组代表 | 评审报告 + lint |
| G2 契约确认门 | 2→3 | PM + 主策划 | 契约完整性检查 |
| G3 集成门 | 4→5 | TA + 开发 | 规范校验报告 |
| G4 测试门 | 5→6 | 测试 + PM | 测试报告 |
| G5 验收门 | 6 | PM | 全链路追踪汇总 |
